# Town07 정지 구간: 실제 원시 기록의 방향·변위 분석

두 실행 모두 원래 속도·가감속 검사는 통과했지만, **XY 곡률 위반은 그대로 남았습니다. 학습 데이터로 승인하지 않았습니다.** 새 주행이나 학습을 실행한 자료가 아니라, 보존된 Town07 직진·목표 정지 기록을 연결해서 분석한 결과입니다.

## 전체 분모와 실패 보존

| 항목 | run_001 | run_002 | 합계 |
|---|---:|---:|---:|
| 원시 20Hz 상태 | 1,472 | 1,462 | 2,934 |
| 미래 64점이 모두 있는 창 | 671 | 666 | 1,337 |
| 재구성한 미래 점 | 42,944 | 42,624 | 85,568 |
| 곡률 위반을 포함한 창 | 145 | 154 | 299 |
| 위반 점 수: 중첩된 미래 창 포함 | 576 | 695 | 1,271 |
| 중복을 합친 고유 100ms 구간 | 60 | 59 | 119 |
| 첫 미래점 / 이후 미래점의 위반 | 57 / 519 | 56 / 639 | 113 / 1,158 |
| 원래 tail 미래 문맥 전용 anchor | 65 | 65 | 130 |

고유 119구간도 119회의 독립 정지가 아닙니다. 같은 경로·조건에서 수행한 두 실행이며, 각 구간의 대표 기록은 중첩 창 중 **최대 곡률 위반**입니다. 통과 사례를 골라낸 것이 아닙니다. 모든 64개 미래 인덱스를 검사했으므로 첫 미래점만 수정해서 해결할 문제도 아닙니다.

## 어느 구간에서 발생했나?

| 위반 시점의 실제 단계 | run_001 | run_002 |
|---|---:|---:|
| 출발 `launch_low` | 2 | 3 |
| 출발 직후 `normal_pid` | 2 | 3 |
| 목표 근처 저속 타력 주행 `coast_low` | 55 | 52 |
| 첫 정지 tail 구간 | 1 | 1 |

위반 시점은 모두 저속입니다. 전체 중첩 위반점의 원시 body endpoint 속도 최댓값은 **0.480 / 0.634m/s**, 100ms XY 구간 평균속도 최댓값은 **0.510 / 0.576m/s**입니다. 정상 이동 순항 시점의 위반은 발견하지 못했습니다. 워밍업 anchor에 포함된 위반도 미래의 출발 시점을 가리키므로, 워밍업 자체의 떨림이라고 해석하면 안 됩니다.

![두 실행의 고유 위반 구간 전체 속도·변위·조향](01_joined_motion.png)

각 점은 한 고유 위반 구간입니다. 가로축은 단계별로 묶은 **구간 순번이며 연속 시간축이 아닙니다.** 색 배경은 출발 / 초기 PID / 저속 타력 / 첫 tail입니다. 원시 body endpoint 속도와 100ms 변위로 구한 평균속도는 다른 관측량입니다. 조향은 API가 보고한 값이지 실제 타이어 힘이나 제어 적용 시각의 증명이 아닙니다.

## 작은 변위와 방향 계산

![원래 허용각·관측 방향 변화·조건부 반올림 상한](02_heading_conditioning.png)

원래 기준 `곡률 0.2 rad/m`을 바꾸지 않았습니다. 그림의 허용각은 **관측된 구간 변위 × 0.2**입니다. body yaw 변화도 함께 표시했지만, XY 변위의 방향 변화와 동일한 값이어야 한다고 가정하지 않았습니다. 정확히 0인 값도 그대로 표시했습니다.

저속 타력 구간의 변위는 **6.82–17.96mm / 7.39–16.82mm per 100ms**입니다. 그중 16/55구간과 17/52구간은 시작·중간·끝 API 조향이 모두 0입니다. 따라서 모든 위반을 변경되는 조향 명령 하나로 설명할 수 없습니다.

일부 저장 좌표의 binary32 간격은 약 **15.26μm**입니다. 노란 표시는 각 pose 성분이 한 번 binary32 최근접 반올림되었다고 가정하고, 기록된 1.425m 기준점 이동을 반영한 **조건부 각도 오차 상한 계산**입니다. 측정한 잡음이나 실제 오차가 아니며, CARLA 서버의 산술 정밀도·물리 기준점을 확인한 결과도 아닙니다.

저속 타력 30/55구간과 24/52구간에서는 이 조건부 상한이 원래 허용각보다 큽니다. 반대로 전체 고유 구간 **13/60개와 18/59개는 관측 방향 변화가 조건부 상한과 고정 관측거리 허용각의 합보다도 큽니다.** 반올림 또는 수치적 떨림이 유일한 원인이라는 결론은 지지되지 않습니다. 이 비교도 완전한 구간 연산에 의한 물리 실현 가능성 증명은 아닙니다.

첫 tail 두 구간의 변위는 **4.053 / 4.383mm**, XY 방향 변화는 **0.14148 / 0.12483rad**, body yaw 변화의 절댓값은 **0.000305 / 0.000301rad**입니다. 이때 endpoint 속도는 거의 0이고 API는 brake=1, steer=0을 보고했습니다. 구간 평균·구간 끝 속도·기준점 이동이 섞인 관측이므로, 이 차이만으로 제어 지연이나 잘못된 물리 위치를 확정하지 않았습니다.

## 그대로 유지한 제한

- 원본 v1/v2 결과, 상태·카메라·라벨·타임스탬프·분할·gate를 변경하지 않았습니다. 위반 구간이나 워밍업/tail을 삭제하지 않았습니다.
- 원래 보간 시각과 가장 가까운 원시 상태의 연결 차이는 최대 74ns입니다. 연결을 위한 비교일 뿐, 원래 시각을 재정렬하거나 보정하지 않았습니다.
- 원시 기록은 `training_data_approved: false`이며, 변환·학습 승인·모델 승격을 하지 않았습니다. 새 학습이나 실제 자율주행 성공을 주장하지 않습니다.
- 다음 수집 전에 기준점·정지 표현과 물리 관측의 차이를 분리하는 검증이 필요합니다. 초기화 시점만 변경하는 재주행으로 목표 근처 107구간까지 해결된다고 가정하지 않습니다.

## 파일과 재현

[summary.json](summary.json)과 [unique_ticks.jsonl](unique_ticks.jsonl)은 원본 v2와 **완전히 같은 바이트**입니다. 119개 구간의 원시 3D 관측, 조향·기어, 몸체 속도·yaw, 방향·변위, 조건부 상한을 모두 확인할 수 있습니다. [original_SHA256SUMS](original_SHA256SUMS)은 원본 manifest이며, [provenance.json](provenance.json)은 12개 원래 입력의 SHA와 분석기·렌더러 SHA, 그래프 순서를 기록합니다. 전체 공개 파일은 [SHA256SUMS](SHA256SUMS)로 검증합니다.

[render_conditioning.py](render_conditioning.py)는 이 고정 자료만 처리하며 새 패키지를 설치하지 않습니다. 저장소 최상위에서 다음 명령은 입력만 확인합니다.

```bash
python3 docs/assets/validation/2026-09-09/portable_e2e_learning_cycle_v1/02_overnight_data_and_learning/06_town07_stop_conditioning/render_conditioning.py --check-only
```

그림을 생성하는 기본 실행은 새 출력 파일이 없는 경우에만 허용됩니다. 이미 공개된 파일을 덮어쓰지 않습니다. Git clone에 포함되지 않는 개인 원시 artifact가 없으면 SHA 검증 단계에서 명확히 중단합니다. 공개 JSON/PNG만 보는 데 해당 원시 artifact나 CARLA/GPU는 필요하지 않습니다.
