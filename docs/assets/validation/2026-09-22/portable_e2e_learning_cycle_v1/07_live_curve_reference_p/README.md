## 이번에 실제 진행한 일

2026-09-22 13:43 KST 로컬 프로세스·GPU 계산 작업·CARLA 포트·작업 잠금을 확인한 뒤, 전용 2100 포트에서 실행했다. 기존 공용 수집기를 수정하지 않고 별도 연구용 worker/wrapper를 추가했다. 공유 runtime lock을 사용하고 각 실행이 생성한 프로세스 그룹만 종료했다. 각 실행의 owner_result에서 소스 보존과 종료 상태를 확인했다.

이 결과는 **CARLA BasicAgent expert 수집 개선 실험**이다. Portable E2E 모델의 자율주행 성공이나 모델 성능 향상을 측정한 것이 아니다. 원격 서버 설치·학습·GPU1 접근은 하지 않았다.

## 변경 내용

- 경로의 곡률과 감속 여유를 반영한 공간 기반 속도 상한을 BasicAgent 요청 속도에 적용했다.
- 기존 장애물/신호등 긴급 제동 판단과 반환 제어값은 변경하지 않았다. 신호등 검사 함수를 미리 호출하지 않는다.
- 속도 요청, 실측 속도, 경로 진행, 횡오차, 페달, 차량 API 신호등 상태를 매 프레임 기록했다. 이 신호등 상태만으로 BasicAgent가 선택한 위험 원인을 확정할 수는 없다.
- 순수 오프라인 SpeedReference.update/adapter를 실차 제어기로 승격한 것이 아니다. 이번 live pilot은 공간 속도 상한만 사용한다. 출발/종점 경계 속도는 cruise로 두고 기존 정지 로직을 유지했다.
- 연구 자료를 학습 승인하지 않는다. 01~03의 제외 표시는 capture_contract.curve_reference_research 안에 있다. 04부터 변환기가 인식하는 최상위 training_data_approved=false도 추가했다. 이전 원본은 소급 수정하지 않았다. 어느 실행도 학습 데이터로 변환하지 않았다.

공통: ClearNoon, Prius, Epic, 물리 20 Hz, 6카메라 10 Hz, ACK 제어, 지면 스폰, lookahead 2 m + 0.2 s. Town01은 이전 M06과 동일 경로·seed를 사용했다.

분모는 warmup/tail을 포함한 **6.4초 미래가 존재하는 모든 카메라 앵커**다. common10 eligibility를 통과한 학습 샘플 수가 아니다. 주행 시간이 달라 분모가 다르며, 반복 seed 통계나 모델 평가도 아니다. M06의 기존 common10 487개와 여기 488개를 혼동하면 안 된다.

P02에서 **첫 실패 원인**이 횡가속도인 구간은 기존 75개에서 0개로 감소했다. 다른 실패에 가려진 횡가속도까지 모두 통과했다는 뜻은 아니다. 가감속 첫 실패는 85→122개, 기하학적 속도 초과는 40→40개다. 따라서 곡선 속도 상한은 유망하지만 전체 해결은 아니다.

P03은 속도 초과 첫 실패가 없어졌지만 곡률 111, 가감속 129, 위치/속도 불일치 8, 이동 범위 2개 실패가 남았다. 10 Hz 감속 최솟값 -12.26 m/s²로 기준 -6을 넘는다. 정지 후 tail의 속도 변화는 통과했으나 정지 직전은 실패했다. 요청 속도와 정지 프로파일을 동시에 바꿨으므로 두 효과를 각각 분리해 주장할 수 없다.

P04는 속도 변화 80, 속도 상한 64, 현재 속도 상한 2개가 첫 실패 원인이다. 10 Hz 급감속 위반 3개는 모두 tail 전환/유지 구간에 있다. 단순 감속 곡선만 적용해서는 출발 가속·최고속도 overshoot·종료 제동을 해결하지 못했다.

P05 대조 실험도 수행했다. 속도 상한 첫 실패는 사라졌으나 위치 변화와 속도 불일치 120, 가감속 44, 적분 거리 불일치 16, 이동 범위 2개가 남았다. 서로 다른 첫 실패 원인이 다른 위반을 가릴 수 있으므로 122→44를 실제 가감속 위반 총량 감소로 해석하지 않는다. 통과율은 P02와 거의 같아 **최고 요청 속도만 낮추는 접근을 해결책으로 채택하지 않았다**.

## 현재 전체 목표에서의 위치

기존 로드맵은 9개 영역 / 30개 세부 기능이다. 이전 자료에서 일부 데이터·계측 근거가 있는 항목은 10개지만 완료율이 아니다. **자체 학습 모델의 승인된 closed-loop 기능은 0/30, 실차 검증도 0/30**이다. 이번은 기본 5개(직진·좌회전·우회전·목표 정지·속도 추종) 중 우회전 데이터와 속도/정지 품질을 다루는 단계다. 기능 헤드는 추가하지 않았다.

기존 K/L 학습은 완료됐지만 DEV 우회전 회귀 때문에 승격하지 않았다. GPU가 비어 있다는 이유로 불합격 데이터를 추가 학습하지 않았다. 이번에 모델 체크포인트를 새로 만들거나 기존 것을 교체하지 않았다.

## 다음 진행 순서와 비용 범위

1. 최고속도 여유 단독 대조는 P05로 완료했다. 다음은 위치 변화/측정 속도 불일치가 발생하는 원시 프레임을 찾고, 시작/종료 저속 제동 구간과 신호등 긴급 제동 경로를 분리 계측한다. 긴급 제동은 완화하지 않는다.
2. 연속된 10 Hz 미래 구간의 위치·속도·가속도 일관성을 검증한다. 불합격을 숨기기 위한 label clipping이나 gate 완화는 하지 않는다. 곡률 실패가 생기는 저속 재출발도 별도로 확인한다.
3. 통과한 실제 수집 자료만 provenance/카메라/경로/물리 검증을 거쳐 TRAIN에 편입한다. 연구용 제외 표시는 검증 없이 제거하지 않는다.
4. 고정 DEV/TEST 분리를 유지하며 원격 pro6000의 개인 venv, GPU0만 사용해 baseline 대비 동등 노출량 재학습한다. 학습 후 우회전·직진 회귀와 로컬 closed-loop를 함께 검사한다.

다음 제어 대조 수집+분석은 오류가 없다면 대략 20~40분 작업 범위다. 학습은 데이터 승인 후 진행하며, 이전 15k-step 실행 약 32분은 참고치일 뿐 새 실험 소요시간 보장은 아니다. 데이터 준비·검증·전송·평가는 별도다. 현재 청구 토큰/잔액의 정확한 수치는 확인할 수 없으며, 시간이나 GPU 학습 시간에서 토큰 비용을 환산하지 않는다.
