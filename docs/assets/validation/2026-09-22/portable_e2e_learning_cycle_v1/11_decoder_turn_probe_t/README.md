## 수행한 일

원격 개인 py312 venv, 승인된 GPU0에서 기존 K1 모델 가중치를 고정하고 DRIVE latent만 최적화했다. 새로운 모델 가중치 학습이나 배포는 아니다. 기존 TRAIN 우회전 중 미래 회전량15도 이상인 구간에서 시간 순서 네 지점을 결정적으로 선택했고, 좌회전 두 구간을 비교용으로 선택했다. 불합격 원본도 이 연구 진단에만 사용했다. DEV/TEST는 열지 않았다.

- 각 입력은 원래 이미지·ego history·route를 사용한 K1 예측과 비교했다.
- 위치 ADE만 최소화하는 조건과 `ADE + 0.2 × speed MAE` 조건을 비교했다.
- 각각 모델 latent 초기값 및 random 초기값에서500step씩 최적화했다. 각 실행의6개 DRIVE 후보를 모두 최적화하고 표본별 가장 낮은 목적함수 값을 보존했다.
- 총4개 조건, 약109.4초. 모델 가중치 hash가 전후 동일함을 확인했다.
- 기존12후보는 DRIVE6+STOP6이다. 첫 실행에서 이 구분을 잘못한 진단 reshape 오류로 중단됐고, 이를 수정·테스트한 v2를 별도 디렉터리에서 실행했다. v1 원본을 삭제하지 않았다.

## 판단과 하지 않은 주장

1. token440/좌회전31에서는 동일 decoder가 매우 작은 오차의 궤적을 만들 수 있었다. 모든 회전을 표현하지 못하는 구조는 아니다. 기존 후보 생성/선택의 개선 여지가 이 장면들에서 직접 확인됐다.
2. token440은 기존 oracle0.31m 대비 선택5.09m이므로 선택 실패도 명확하다. 반면90도 두 장면은 기존 최선 후보부터 부정확했다.
3.90도 두 원본 정답은 각각 횡가속도 runtime gate를 초과한다. 안전 제약을 가진 decoder에 이를 시간까지 동일하게 모방하도록 요구하면 충돌할 수 있다. 원본 검사 실패와 decoder 피팅 잔차는 그 가능성의 근거이지, 잔차 전부의 원인을 증명한 것은 아니다.
4. 최적화한6장면의 선택된 geometry/joint 결과12개는 기존 runtime gate를 통과했다. **안전 gate 통과와 정답 모방 오차는 별개**다.
5.500step·두 초기값은 전역 최적을 보장하지 않는다.1.58/3.37m를 구조의 수학적 최소 오차라고 부르지 않는다. 모델 가중치·구조·물리 한계·runtime gate는 수정하지 않았다.
6. 이번 결과는 실제 모델 주행 개선이 아니다. 정답으로 직접 최적화한 출력을 모델 inference라고 표시하거나 학습 정답으로 자동 승인하지 않는다.

## 다음 개선 작업의 분기

- **표현 가능한 장면:** 신경망이 해당 latent/궤적을 예측하게 하는 학습 대조를 설계한다. 현재 K1 후보와 직접 최적화 사이의 차이가 큰 구간을 분리하고, 원본 정답 대신 진단 최적화 출력을 쓰는 경우에는 별도 합성 teacher 실험으로 명시한다. 자동 치환하지 않는다.
- **90도 회전:** 경로 형상과 진행 속도를 분리하는 표현을 기존 방식과 비교한다. 시간을 바꿔도 경로를 못 따라가는지와, 원본 속도 요구가 물리 한계를 넘는지를 먼저 분리한다. 곡률/횡가속도 제한을 풀어 오차만 낮추지는 않는다.
- 구조 변경을 채택하려면 동일 표본/최적화 예산 비교에 이어 네트워크 재학습, 고정 DEV 비퇴행, 미사용 경로 closed-loop 순으로 확인한다. 이 단계들은 아직 실행하지 않았다.

기존9영역/30기능 중 기본 좌우회전의 생성/선택을 다루는 단계이며, 승인된 자체 모델 closed-loop 기능0/30은 변함없다. 다음 표현 대조 구현·검산은 대략30~60분 작업 범위로 예상하며 학습/주행 시간은 별도다. 정확한 과금 토큰 사용량은 확인하지 못했다.
