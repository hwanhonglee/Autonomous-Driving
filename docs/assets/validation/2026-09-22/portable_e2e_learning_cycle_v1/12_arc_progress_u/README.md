# 회전 개선 U: 경로는 더 가까워졌지만, 안전한 90도 회전은 아직 미해결

## 지금 결론

**아직 “회전이 괜찮아졌다”고 할 수 없습니다.** 경로 모양과 진행 속도를 분리한 연구용 코드를 구현하고 비교했습니다. 큰 우회전 두 장면에서 정답 경로에 가까워졌지만, 그대로 사용하면 기존 안전 검사를 통과하지 못했습니다. 감속과 경로 평활화를 적용하면 일부 짧은 구간이 검사에 통과했으나, 90도 회전 전체를 끝낸 성공 사례는 확인하지 못했습니다.

이번 작업은 기본 주행의 **곡선·우회전 경로 생성과 속도 조절**에 해당합니다. 장애물 회피나 차선변경 기능을 추가한 작업은 아닙니다. 전체 기능 완료 수를 늘릴 근거도 아닙니다.

## 무엇을 실제로 실행했나

- 원격 Pro 6000: 개인 Python 가상환경과 지정 GPU 0만 사용해, 기존과 동일한 TRAIN 장면 6개에서 연구용 경로 표현을 비교했습니다. 500단계씩 4개 최적화 조건을 실행했고 약 35초 소요됐습니다.
- 로컬: 장면 6개 × 속도 배율 4개 = 24조건에 대해 감속·경로 평활화 전후를 계산하고 기존 안전 검사를 적용했습니다.
- 이번에는 모델 가중치를 학습하지 않았습니다. 정답을 보면서 장면별 내부 값을 맞추는 표현력 진단입니다. 새 모델 체크포인트나 실제 추론 성능 개선 결과가 아닙니다.
- CARLA·Autoware 주행은 실행하지 않았습니다. 다른 테스트 프로세스를 중단하거나 패키지를 설치하지 않았습니다.

## 무엇이 좋아졌고, 무엇이 여전히 문제인가

아래 오차는 경로 점과 정답 위치 사이의 평균 거리입니다. 작을수록 정답에 가깝지만, 안전한 주행을 의미하지는 않습니다.

| 동일한 큰 우회전 장면 | 이전 T 경로 표현 | 이번 U 경로 표현 | 이번 결과의 기존 안전 검사 |
|---|---:|---:|---|
| 000464, 약 89도 | 1.58 m | 0.20 m | 실패 |
| 000487, 약 90도 | 3.37 m | 0.59 m | 실패 |

중요한 차이가 있습니다. U는 입력 경로를 따라 위치를 만들기 때문에, T의 위치 생성에 내장된 방향·곡률 제한을 그대로 유지하지 않습니다. 따라서 이 숫자를 **같은 물리적 제약 아래에서 모델이 좋아졌다는 증거로 해석하면 안 됩니다.** 속도 제한과 외부 안전 검사 기준은 유지했고, U에서 선택한 6개 장면의 joint 최적화 결과는 모두 외부 검사에 실패했습니다. 작은 회전 일부는 오히려 위치 오차가 증가했습니다.

감속 비교에서는 실제 현재 속도에서 시작해 최대 2 m/s²로 속도를 바꾸도록 했습니다. 경로를 부드럽게 하고 차량 위치에서 이어지도록 수정하자, 24조건 중 검사 통과가 **3개에서 11개**로 늘었습니다. 그러나 이는 서로 독립적인 주행 성공 11회가 아닙니다.

- 000464: 통과 조건에서는 6.4초 뒤에도 방향 변화가 약 3도 이하라, 본격적인 90도 회전을 아직 하지 않았습니다.
- 000487: 통과 조건에서는 약 30도까지만 진행했습니다.
- 회전을 끝까지 진행하는 더 빠른 조건은 속도 또는 횡가속도 검사에 실패했습니다.

즉, **천천히 가서 어려운 구간에 아직 도달하지 않은 결과를 회전 성공으로 세지 않았습니다.**

## 다음에 해결해야 할 것

1. 평활화한 경로의 실제 길이를 다시 계산해, 위치 변화와 출력 속도가 서로 맞도록 합니다. 현재 평활화는 원래 경로 길이를 사용하므로 이 불일치가 남을 수 있습니다.
2. 회전에 들어간 뒤 속도를 일괄 줄이는 방식에서, 앞쪽 곡률을 보고 미리 감속하는 방식으로 바꿉니다.
3. 짧은 예측 구간의 통과뿐 아니라, 회전 진입부터 탈출까지 이어서 진행되는지 확인합니다. 경로 끝에서 위치만 고정되고 속도가 남는 경우도 실패로 처리해야 합니다.
4. 안전하고 일관된 경로·속도 목표를 확인한 뒤 모델 학습에 반영합니다. 이후 미학습 장면 평가와 CARLA 폐루프 주행을 거쳐야 실제 모델 개선으로 인정할 수 있습니다.

이 단계들을 통과하기 전에는 배포 모델을 교체하지 않습니다. 추가 기능 헤드보다 기본 주행 회복이 우선입니다. 전체 학습·주행 소요 시간은 아직 산정되지 않았으며, 이번 진단 실행 시간과 혼동하면 안 됩니다. 계정 토큰 잔량이나 실제 과금액은 이 기록으로 확인할 수 없습니다.
