## 주행 — 왜 AF를 학습하는가

이전 AD는 원래 손실만 사용했고, AE는 후보 순위 손실과 기존 출력 보존 손실을 함께 추가했습니다.
AE가 AD보다 나빴으므로 두 변경 중 어느 항목이 영향을 줬는지 분리합니다.

| 조건 | AD | AE | 이번 AF |
|---|---|---|---|
| 초기 가중치 | K1 | K1 | K1 |
| 추가 step | 15,000 | 15,000 | 15,000 |
| 후보 순위 손실 | 없음 | 0.2 | 0.2 |
| 기존 출력 보존 손실 | 없음 | 0.5 | **0** |

TRAIN 2,787개, 동일 샘플 순서·seed·batch 4·학습률 3e-5·전체 모델 학습을 유지합니다.
AE에서 보존 손실 가중치만 제거합니다. teacher 초기화/계산도 유지해 난수 소비 차이를 만들지 않습니다.
새 기능 head, DEV 라벨 학습, 자동 모델 교체는 없습니다. optimizer는 새로 시작합니다.

예상 30–40분은 직전 실행 기반이며 보장 시간이 아닙니다.
완료 후 동일 DEV 665개에서 우회전·직진 ADE/FDE·속도와 K1 비퇴행/strict gate를 평가합니다.
이 DEV는 반복 관측된 연구 자료로 좌회전·독립 정지·새 Town 일반화 검증은 아닙니다.
AD/AE/AF 비교는 한 seed의 조건 분리 실험이며 통계적 인과 입증이나 성능 향상 보장이 아닙니다.

원격 출력: `runs/diagnostics/full_recovery_af_20260922_v1`.
실행 스크립트: `run_recovery_ae.py --objective rank_only` (역사적 파일명 유지, 실행 이름은 AF).

## 지도 — 무엇을 바꿨고 결과는 어떤가
