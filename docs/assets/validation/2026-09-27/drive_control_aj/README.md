# 주행 자료 개선 AJ — 출발은 개선, 목표 정지는 아직 미해결

<!-- HH_260906 - Report control/data improvements separately from model learning and driving-function approval. -->

## 먼저 결론

**출발 때 튀는 가속은 줄였습니다. 하지만 부드러운 감속과 정확한 목표 정지를 함께 만족시키지는 못했습니다.**
따라서 새 자료로 주행 모델을 학습하거나 운용 모델을 교체하지 않았습니다.

로컬에서 같은 Town01 우회전 경로를 **새로 8회** 수집해 이전 기준 1회와 비교했습니다.
수집·전체 카메라 검사·미래 궤적 감사·PNG/GIF 생성은 완료됐습니다. 관련 회귀 검사 **224개가 통과**했습니다.
현재 이번 작업의 CARLA 수집이나 새 학습은 실행 중이 아닙니다.
목표 속도는 **9 km/h**입니다. 30 km/h 또는 모든 Town에서의 주행 성능 검증이 아닙니다.
운전한 것은 CARLA BasicAgent 기반 수집 제어기이지, 자체 학습 모델이 아닙니다.

## 무엇이 실제로 개선됐나

| 항목 | 이전 기준 A | 개선 실험에서 확인한 결과 |
|---|---:|---|
| 최대 가속 | +4.06 m/s² | 출발만 제한한 E에서 **+2.35 m/s²**, 기존 +2.9 기준 안 |
| 급감속 | −16.51 m/s² | 정상 제동을 없앤 G/H/I에서 최저 **약 −2.3~−2.4 m/s²**, 기존 −2.9 기준 안 |
| 목표에서 정지 | 정지는 했지만 급감속 검사 탈락 | 부드러운 감속 설정은 목표를 지나쳐 실패 |
| 목표 통과 속도 | 해당 없음 | G **1.327 → H 0.345 → I 0.158 m/s**, 여전히 정지 성공 아님 |
| 새 주행 모델 가중치 | AH | **변경 없음** |

가속과 감속의 숫자를 각각 다른 실험에서 뽑아 하나의 완성된 성공으로 합치지 않습니다.
I의 경우 실제 가감속 범위는 −2.32~+2.35 m/s²이지만 **목표 정지 실패**입니다.

## 왜 단순히 페달 상한을 낮추는 것으로 끝나지 않았나

1. **초기화 시점 변경만으로는 효과가 없었습니다.** 기준 A와 B의 가감속·도착 결과가 동일했습니다.
2. **가속 상한을 주행 내내 낮추면 다른 상황을 만납니다.** C/D는 이동 시간이 길어졌고,
   정상 제동 상한을 초과한 0.5 제동 기록이 나타났습니다. BasicAgent 비상 제동 경로는 유지했으며,
   원인이 신호등인지 다른 위험 판단인지까지는 원시 기록에 없어 확정하지 않습니다.
3. **출발에만 상한을 낮추자 불필요한 순항 저하를 피했습니다.** E는 출발 상한 0.13,
   측정 속도 0.5 m/s 도달 후 원래 순항 상한 0.20을 사용했습니다. 단일 경로에서 재출발까지 검증한 것은 아닙니다.
4. **작은 정상 제동도 큰 속도 변화와 연결됐습니다.** F는 정상 브레이크 상한 0.02였고
   비상 제동 기록은 없었지만, 20 Hz 한 구간에서 속도 1.074→0.0075 m/s가 관측됐습니다.
   명령 정렬은 맞았습니다. 이 기록만으로 CARLA 내부 타이어/정지 마찰/수치 해석의 원인을 확정할 수는 없습니다.
5. **정상 제동을 없애면 속도 급변은 줄지만 정지거리가 길어집니다.** G→H→I로 감속 목표를
   앞당기고 여유 거리를 늘려 목표 통과 속도를 낮췄으나, 목표 앞 완전 정지에는 아직 실패했습니다.

비상 제동은 한 번도 제거하거나 약화하지 않았습니다. 정상 제동 0 실험에서도 위험 판단의 비상 제동과
실패 시 정리·중단 제동은 유지했습니다. 목표 초과는 즉시 실패로 보존했습니다.

## 실험 순서 — 같은 조건에서 무엇만 바꿨나

| 실험 | 변경 | 결과 |
|---|---|---|
| A, 9월 26일 기준 | throttle 0.20 / normal brake 0.15 | 도착, 급가감속 실패 |
| B | 초기화만 after_bootstrap | A와 같은 가감속 결과 |
| C | 전체 주행 throttle 상한 0.13 | 가속 완화, 주행 중 비상 제동 관측·감속 실패 |
| D | C의 normal brake 상한 0.15→0.02 | 비상 제동 관측, 목표 초과 |
| E | 출발만 0.13, 0.5 m/s 이후 0.20; brake 0.15 | 출발 개선, 목표 정지 급감속 실패 |
| F | E에서 normal brake 0.02 + 계획 감속 1.0→0.4 m/s² | 목표 도착, 정상 제동 급감속 실패 |
| G | F에서 normal brake만 0 | 가감속 검사 범위 안, 목표 초과 1.327 m/s |
| H | G의 계획 감속 0.4→0.12 m/s² | 가감속 범위 안, 목표 초과 0.345 m/s |
| I | H의 계획 정지 여유 거리 0.75→2.0 m | 가감속 범위 안, 목표 초과 0.158 m/s |

F는 두 제어 인자를 함께 바꾼 실험이므로 단일 인자의 인과 비교라고 하지 않습니다.
작은 계획 감속 값은 더 긴 거리에서 낮은 목표 속도를 요청한다는 뜻이지, 실제 감속을 보장하는 값이 아닙니다.
같은 seed라도 제어가 달라지면 주행 시각과 만나는 동적 신호 상황이 달라질 수 있습니다.

공통 조건: Town01 p03, Prius, ClearNoon, seed 2026092601, Epic, 원시 상태 20 Hz, 6카메라 10 Hz,
warmup 3.5초, 성공 시 tail 6.5초. 목표 1 m 이내·속도 ≤0.1 m/s·2초 유지·목표 초과 금지 기준은 그대로입니다.
물리 설정은 관측상 50 ms tick, substepping 활성, 최대 substep 10 ms였습니다.

## 궤적·카메라까지 검사했습니다

[최종 원본 검사 요약](final_audit/summary.json) · [전체 비교 그래프](final_audit/control_comparison.png)

- 6개 카메라의 실제 JPEG, 프레임·시각 일치, 전체 기록 범위와 명령 정렬을 검사했습니다.
  기준 포함 **30,756장 전부** 이미지/메타데이터 검사 통과, 명령 정렬 불일치 **0건**입니다.
- 정지 전후를 자르지 않고 기존 6.4초 미래 XY/속도/곡률/횡가속도 검사를 적용했습니다.
- A와 E는 각각 완전한 미래 창 406개/420개 중 곡률 실패 194개/195개였습니다.
  창들이 서로 겹치므로 194번의 독립적인 주행 실패라는 뜻은 아닙니다.
- D/G/H/I처럼 경로 끝을 지난 경우 기존 경로 계약이 일부 anchor를 거부합니다.
  해당 회차의 전체 미래 검사를 `REJECTED_ROUTE_END`로 남기며, 검사 불가를 통과 또는 실패 0개로 표시하지 않습니다.
- 충돌·차선 침범 센서 0회는 차량 차체 전체가 의도 차로 안에 있었다는 독립 증명이 아닙니다.
- 실험 코드에는 `development_only=true`, `training_data_approved=false`를 명시했습니다.
  스칼라 가감속 통과만으로 Common10 변환·학습에 편입할 수 없습니다.

## 다음 개선은 무엇인가

다음은 **측정 속도·남은 거리 기반 정지거리 추정과 저속 유지 제동 전환**을 설계할 차례입니다.
이번 결과로 출발 상한과 순항 상한은 분리해야 하고, 정상 제동을 단순히 약하게 만드는 것만으로는
급감속을 해결하지 못한다는 근거를 확보했습니다. 정지 여유 거리 하나를 계속 수동으로 맞추는 방식의
조건 의존성을 줄여야 합니다.

1. G/H/I의 무제동 감속 곡선으로 속도별 실제 이동거리를 계측하고, 정지거리 예측 오차를 별도로 평가합니다.
2. 기존 정지 전환·무페달 계측을 재사용하여, 낮은 측정 속도에서만 유지 제동으로 전환하는 조건을 검증합니다.
   목표 거리·유지 시간·가감속·곡률 기준은 완화하지 않습니다. 실제 계측 없이 성공을 가정하지 않습니다.
3. 유효한 이동 회전/정지 자료가 확보되면 별도 소스·자료 승인 후 주행 모델을 재학습합니다.
   직진 자료도 유지하고, AH 대비 직진 비퇴행과 회전 후보 선택 오류를 함께 평가합니다.

예상: 다음 제어 설계·검사·제한된 실험은 **30~90분 연구 범위**, 데이터가 승인된 뒤 주행 학습·평가는
기존 실측 기준 **약 30~40분**입니다. 실패가 이어지면 더 걸리며 학습 시작 시각을 보장하지 않습니다.
후속 작업의 토큰은 대략 **1만~2만 토큰 계획 범위**이고 정확한 실측이나 청구 예상액은 아닙니다.
