## 실행 순서와 단일 요인 A/B

1. **수집·포장 코드의 자격 조건 수정과 단위 검사부터.** 현재 `collect_carla_mapping_probe.py`는 Town01과 고정 Town06 p06만 허용하고, `prepare_map_expansion_ai.py`는 Town01을 강제하며 XY 거리 검사를 동일 좌표계로 가정한다. 두 Town03/07 경로의 SHA를 정확히 허용하되 임의 Town 개방은 피한다. 확장 계약은 다른 Town의 거리 비교를 거부하고, 기존 TRAIN 배열 prefix·DEV 파일 SHA 보존, 신규 경로의 소유 증거와 class pixel count를 검증한다. 평가기는 Town07를 **TRAIN 패키지와 별도 경로**에서 읽어 원본 640×360 및 0.25m 보존 결과를 모두 기록한다. 이 선행 작업 없이는 GPU 학습을 시작하지 않는다.
2. 소유 CARLA가 다른 작업과 겹치지 않는 때 Town03 straight/right를 각각 수집한다. 사전 소스/경로 해시 및 모든 물리/센서 체크를 통과한 경우에만 기존 TRAIN에 추가한 새 manifest를 만든다. 별도 Town07 straight/right를 같은 방법으로 수집하지만, 봉인된 평가 디렉터리에 두고 학습 코드에서는 읽을 수 없게 경로·해시를 검사한다. Town07 캡처 자체의 무결성 검사는 필요하지만, **모델별 성능이나 샘플 예측 화면은 학습 전 확인하지 않는다.**
3. **A/B의 변경 요인은 TRAIN 프레임 구성 한 가지**이다. A는 고정 AI v2 체크포인트; B는 동일 `MapPerception` 구조·640×360 입력·seed·2,000 step·batch 8·optimizer·TRAIN-only crop·loss 공식으로 *처음부터* 학습하되 기존 Town01 TRAIN에 자격을 통과한 Town03 두 경로만 더한다. 새 TRAIN 클래스 빈도에서 기존 공식으로 가중치를 재계산하는 것은 이 데이터 추가의 예정된 결과이고, 별도 임의 가중치 튜닝을 하지 않는다. 물리 GPU **0만**, PRO6000의 `/home/pro6000/personal/hwanhong` 개인 venv/작업 공간만 사용한다. 패키지 설치·GPU 1 사용·기존 작업 중단은 하지 않는다. GPU 0이 점유 중이면 대기하거나 이 실험을 미실행으로 기록한다.
4. 학습 종료와 checkpoint/코드/data SHA 고정 후 A와 B를 **동일한 Town07 두 경로에 단 한 번** 추론하고, 두 경로별·합계 IoU/정밀도/재현율/혼동행렬, GT 차선→표지판 픽셀, GT 표지판→other 픽셀, RGB·oracle·A·B 전체 화면 PNG를 생성한다. Town01 DEV도 같은 코드로 확인하지만 이미 반복 사용한 개발 게이트이지 독립 증거가 아니다. Town06 p06은 기존 실패와 비교하는 진단용으로만 사용하고 채택 점수에 포함하지 않는다.

진행 기록: 단계 1 중 수집기의 **정확한 경로 바인딩만 구현**했다. `--town03-generalization-train`과 `--town07-generalization-test`는 위 각 두 SHA256, 일치하는 CARLA 월드, 240장 물리 BasicAgent 수집과 명시적 신호등 무시 옵션만 허용한다. Town07 모델 지표는 계속 봉인 상태다. 기존 Town01/Town06 동작을 포함한 관련 CPU 검사 **95개가 통과**했다. 포장·평가 코드, CARLA 수집, GPU 학습은 이 기록만으로 완료된 것이 아니다.

## 미리 고정한 판단 기준

이는 **한 번의 탐색 A/B를 통과했다고 자동 배포한다는 의미가 아니다.** Town07 두 경로 각각에서 B의 도로·차선 IoU가 A보다 하락하지 않아야 하고, 두 경로 합계에서 도로 **+5%p 이상**, 차선 **+5%p 이상**, 7-class mIoU **+3%p 이상** 개선되어야 *교차-Town 개선 신호*로 부른다. 또한 두 경로 각각의 B 도로 IoU **80% 이상**, 차선 IoU **50% 이상**이어야 *기초 인식 품질 관문*을 통과한다. 이 절대 관문에 못 미치면 상대 개선이 있어도 “아직 부적합”이다. Town01 DEV에서는 AI v2 대비 도로 ≤1%p, 차선 ≤2%p, mIoU ≤2%p 하락만 허용하고 표지판 IoU·정밀도는 AI v2 이하로 내리지 않는다. 이 기준은 Town07 수치를 보기 전에 고정한다.

캡처/해시/분할/자격 조건 중 하나라도 실패하면 평가를 보류한다. Town07 점수를 본 후 경로·임계값·학습 step/seed를 바꾸어 같은 Town07를 재사용하면 더 이상 이 단회 홀드아웃이라고 부르지 않는다. 이 pilot이 통과해도 다른 날씨·야간·추가 Town·실물 센서의 독립 자료와 사람 검토, 시간 안정성·누적 지도 품질·10Hz 전체 경로·실차 안전 검증 전에는 **지도 모델 승격, HD 지도 완성, 주행 모델 탑재를 금지**한다.

## 표지판 과제는 별도 실험

기존 Town01 DEV 표지판 정밀도 **3.293%**, IoU **3.157%**는 낮고, 기존 sign-scale A/B는 재현율 증가와 함께 오검출이 늘어 탈락했다. Town06에서는 오검출 원천이 `other`가 아니라 주로 차선으로 바뀌므로 지금 `traffic_sign` loss 가중치만 낮추면 두 도메인을 동시에 고친다고 기대할 수 없다. 광범위한 도로·차선 분할을 회복한 뒤, *고정 TRAIN에서의 표지판 loss weight 한 요소* 또는 물체 단위 검증 자료 추가를 **별도 사전 등록 A/B**로 진행한다. 현 AI v2 TRAIN에는 프레임 전체 1–4 px 표지판 0장, DEV에는 31장이었다. Town06의 1–4 px 8-연결 **조각** 1,499개는 읽을 수 있는 표지판 객체 1,499개가 아니며, 기존 Town06 작은 표지판 TRAIN 편입 실패를 뒤집지 않는다.

## 예상 작업량과 한계

소유 CARLA 4경로를 순차 실행하고 원본 해시/중복 제거/전송을 해야 하므로 전체 소요는 수집 자원 충돌과 경로 성공 여부에 좌우된다. 직전 표지판 A/B의 **GPU 0 학습 자체**는 2,000 step에 76.74초였지만, 이는 새 데이터 포장·전송·학습/평가 코드 보수·Town07 평가 시간을 포함하지 않는 과거 실측이다. 따라서 총 시간이나 토큰/비용을 확정하지 않는다. 계산 예산은 **GPU 0에서 우선 1개 학습 후보, 2,000 step**으로 제한하고 실패 시 추가 학습을 자동 반복하지 않는다. 외부 패키지 설치는 계획에 없다.
