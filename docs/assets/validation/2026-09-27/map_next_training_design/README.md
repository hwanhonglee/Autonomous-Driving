## 다음 관문 — 순서대로, 실패하면 중지

1. **p02 원본/객체 자격.** [소유 원본 감사](../map_town02_p02_train_scout/summary.json)의 경로·source·RGB/semantic 240쌍·충돌 0·live/replay·0.25m 보존 232장 해시를 동결한다. 사람 검수자는 태그 8 연결 성분을 시간에 걸쳐 *실제 표지판 객체별*로 묶고, 각 객체의 첫/중간/최근거리 RGB·oracle 전체 화각과 확대를 대조한다. 객체 검수 표본·추적 규칙과 전체 태그 8 픽셀 중 검수 범위를 **결과를 보기 전에** 고정한다. 이 새로운 중·대형 목적에는 **서로 다른 RGB 확인 표지판 ≥3개**, **각각 5px 이상인 확인 객체가 있는 보존 프레임 ≥24장**, 검수 범위가 전체 태그 8 픽셀의 **≥95%**, 검수 범위 안의 비표지판/정합 불명 픽셀 **≤5%**를 사전 자격으로 둔다. 프레임 수는 독립 객체 수가 아니다. 원본 p02의 1–4px **0/232 실패는 그대로** 둔다. 도로·차선 경계도 최소 시작/중간/끝 전체 화각에서 RGB/라벨 정합·가림을 검수한다. 기준 실패 시 p02를 편입하지 않고 선택된 실패를 보존한다.
2. **표지판을 평가할 DEV 확보.** Town05_Opt **우회전 p00**(카탈로그 SHA256 `2f7a25e8ace753bfdd412ae7ef65710a001d1f4b1ecd5765f3ee7b021ced29e3`)을 *site-level DEV* 후보로 사전 고정하고 별도 소유 Epic 640×360·90°·10Hz 240프레임 정찰 계획/경로 가드를 먼저 작성한다. 이 경로는 이미 주행 개발 사이트이고 지도 TRAIN에서는 제외한다. 수집 무결성은 위와 동일, 0.25m 보존 ≥120장, RGB 확인 표지판 객체 ≥3개 및 5px 이상 확인 객체가 있는 보존 프레임 ≥24장을 요구한다. **아직 수집하지 않았고 표지판 존재도 미확인**이다. 실패 시 다른 DEV를 결과를 보며 즉석 선택하거나 Town05 p00의 1–2px 점수로 대신하지 않는다. sign-capable DEV가 없으면 이후 pilot은 연구용 도로·차선 진단까지 가능하되 **표지판 비퇴행·모델 승격 판정은 불가**하다.
3. **동일 코드의 단일 요인 학습 계획을 실행 전 잠금.** p02와 DEV가 모두 통과한 뒤 기존 AI v2 Town01 TRAIN **497장**·DEV **118장**의 원본/순서/manifest를 보존하고 p02의 자격 프레임만 TRAIN에 추가한다. 새 훈련기에서 **D0=Town01만**, **D1=같은 Town01+p02**를 각각 scratch 학습하여 변경 요인을 *TRAIN 출처 구성 하나*로 제한한다. 두 팔의 `MapPerception`, 7클래스 RGB 640×360, TRAIN-only crop, 기존 **Town01 기준 `sqrt_frequency` 클래스 가중치 고정**, 균등 TRAIN 프레임 샘플러, seed `20260922`, AdamW `3e-4`/weight decay `1e-4`, batch 8, 2,000 step을 동일하게 한다. D0가 보관 A를 Town01 DEV에서 재현하지 못하면 D1 비교 전에 중지해 코드/환경 차이를 조사한다. p02 포함 시 클래스 가중치를 재계산하거나 7:1 Town03 복습·표지판 가중치·새 head를 동시에 바꾸지 않는다. 정확한 포장 해시·소스·baseline 허용 오차·새 출력 경로는 **학습 전에** 별도 사전 등록하고 검사를 통과해야 한다.
4. **고정 DEV 판단.** D0/D1을 같은 Town01 118장과 Town05 직진 p00 232장, 그리고 자격을 통과하면 Town05 우회전 p00에 평가한다. Town01에서는 보관 A 대비 도로 IoU **≥97.751%**, 차선 **≥89.233%**, 7클래스 평균 **≥58.121%**, 표지판 IoU **≥3.157%**·정밀도 **≥3.293%**를 모두 요구한다. Town05 직진에서는 D1이 D0 대비 도로·차선 각각 **+5pp 이상**, 절대 도로 **≥80%**, 차선 **≥50%**를 요구한다. sign-capable Town05 DEV에서는 D1의 표지판 IoU·정밀도가 D0보다 낮지 않아야 한다. 같은 장면 연속 232장을 독립 반복으로 보고 신뢰도를 과장하지 않는다. 어느 기준이든 실패하면 탈락이다. 모두 통과하더라도 Town07 봉인 TEST는 평가기·지표·횟수·자료해시가 별도 고정될 때까지 열지 않고, 자동 배포도 하지 않는다.

## 자원·시간과 이번 작업의 경계

이번 문서는 읽기/계획만 수행했다. **CARLA·SSH·GPU·패키지 설치·새 학습·모델 예측을 실행하지 않았다.** p02 객체 검수는 수십 분 이상(추정 30–90분), 신규 Town05 DEV의 소유 수집/감사와 포장·사전 검사에는 추가 시간이 필요해 전체 완료 시간을 확정할 수 없다. 이전 동일 계열의 2,000-step 물리 GPU0 학습 1회는 **약 75–77초**였으므로 D0/D1의 계산 핵심은 유휴 GPU0에서 약 **2.5분+사전 검사/전송/평가**가 출발 추정치이지 완료 약속이 아니다. 그때도 PRO6000 **물리 GPU0만** `/home/pro6000/personal/hwanhong/portable_e2e` 개인 작업공간의 기존 `venvs/py312`에서 사용하고, GPU1·공용 환경·시스템 패키지는 건드리지 않는다. GPU0이 다른 작업에 점유 중이면 중단/대기하며 사용자 작업을 끊지 않는다. 토큰/서비스 크레딧 잔액은 이 실험 비용에서 계산할 수 없다.

**보다 안전한 대안:** 객체/DEV 관문이 미충족이면 GPU 학습을 서두르지 않고 Town05에서 A가 도로를 보도로 오인한 위치, p02의 표지판 객체 반복/라벨 오류, Town01의 표지판 FP를 원본 해시 기반으로 먼저 고정 감사한다. 이것은 후보 점수에 맞춰 데이터를 고르는 반복 학습보다 직접적인 결함 분리다. 다음 모델 구조 변경은 D0/D1의 데이터 요인 결과를 본 뒤 별도 가설로 다룬다.
