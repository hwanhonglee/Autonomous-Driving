# Town05_Opt 지도 DEV: C의 도로·차선은 회복, 모델 채택은 여전히 보류

<!-- HH_260906 - Report the selected Town05 DEV gain without overriding prior protection failures. -->

**결론:** 동일한 Town05_Opt Epic 원본에서 미채택 지도 후보 C가 기존 AI v2 A보다 **도로와 차선 표시를 훨씬 잘 분할**했다. 하지만 이는 개발용 단일 경로의 첫 **94.31 m**에 대한 결과다. C가 이미 실패한 Town01 DEV 보호 관문은 그대로이고, Town05에서 신호등 구조물 성능은 오히려 떨어졌다. 따라서 **C를 채택하거나 배포하지 않는다.** 이 비교는 자동 정밀지도 생성, Autoware 자율주행 화면, learned-control 폐루프 주행 또는 실차 성능 검증이 아니다.

모델 점수를 열기 전에 [평가 계획](PLAN.md)에 입력·두 체크포인트·분모·주 지표·그림 프레임·비채택 조건을 고정했다. [Epic 원본 감사](../map_town05_dev_capture/README.md)에서 소유 실행·source archive·충돌·live/replay·전체 240쌍·0.25m 보존 232장과 원본 해시를 확인했다. 과거 **Low** 수집은 Epic과 섞지 않았다. 실행기는 원본 감사 JSON SHA-256 `d64d77bf4f1d02892f59ac9debd18489c5acbf38842ec81ac4398f7052b950d1`, 계획 SHA-256 `1c6ecba4f3cf85df1df833414cd53810b8b376c227c687a4345997683ae2644e`, AI v2 체크포인트 `ae489cd…`, C 체크포인트 `864de725…`를 검사한 뒤 CPU 추론을 시작했다.

## 핵심 결과: 0.25 m 보존 232장

| 클래스/지표 | A: 기존 AI v2 | C: 7:1 복습 후보 | C−A |
|---|---:|---:|---:|
| 도로 IoU | **36.314%** | **93.040%** | **+56.727 pp** |
| 도로 precision / recall | 70.725% / 42.738% | 95.099% / 97.727% | 참고 |
| 차선 표시 IoU | **9.006%** | **62.148%** | **+53.142 pp** |
| 차선 표시 precision / recall | 52.631% / 9.801% | 72.950% / 80.759% | 참고 |
| 신호등 구조물 IoU | 3.978% | **0.741%** | −3.237 pp |
| 7클래스 평균 IoU | 15.509% | 36.827% | +21.318 pp |
| 표지판 IoU — **진단 전용** | 0% | 0% | 채택 기준 아님 |

두 모델 모두 원본 RGB 640×360을 `float32 / 255`로 입력받았고, CARLA 의미 라벨은 **평가 정답으로만** 썼다. 혼동행렬의 행은 정답, 열은 예측이다. A가 실제 도로 픽셀 **2,536.8만 중 약 1,170.3만을 보도로** 잘못 분류한 것이 도로 IoU 하락의 큰 원인이다. 실제 차선 픽셀 **128.9만 중 A가 맞힌 것은 12.6만**, C는 104.1만이다. C에서도 신호등 구조물과 표지판은 해결되지 않았다. 240장 전체에서도 도로/차선 IoU는 A **35.988%/8.890%**, C **93.119%/61.937%**로 같은 방향이며, [기계 판독 원본·보존 지표와 7×7 혼동행렬](summary.json)에 둘 다 있다.

표지판 정답은 보존 232장 합계 **256픽셀**이고 각 원본 프레임에 **1–2픽셀**뿐이다. A가 표지판으로 예측한 184,785픽셀, C의 8,977픽셀 중 정답과 일치한 픽셀은 둘 다 0개다. 이 수치는 픽셀 의미 분할이며 표지판 **개체 검출률**이 아니다. 이 원본의 표지판 점수로 모델을 순위화하거나 작은 표지판 학습 자료의 적격성을 선언하지 않았다.

Town05 진단상 도로 ≥A−1 pp·차선 ≥A−2 pp 표식은 C가 통과했다. **그러나** [기존 Town01 DEV 평가](../map_town_rehearsal_c/README.md)에서 C는 A 대비 차선 IoU **−2.528 pp**, 표지판 IoU **−0.888 pp**, 표지판 정밀도 **−0.952 pp**로 고정 보호 기준에 실패했다. 따라서 `automatic_promotion=false`, `deployment_approved=false`를 유지한다. Town05의 232장은 같은 경로·날씨의 연속 프레임이므로 232개의 독립 실험이나 맹검 TEST로 해석하지 않는다. 지도 Town07 최종 TEST는 열지 않았다.

## 재현·검증 경계

[평가 코드](../../../../../tools/e2e/evaluate_map_town05_dev.py)는 이전 Town06 도구의 7클래스 정의와 같은 의미를 사용하되 Town05 원본·Epic 감사·AI v2/C 해시를 별도로 고정한다. 결과를 덮어쓰지 않도록 [예측 NPZ](predictions.npz)·PNG·요약을 **새 파일로만 생성**하고 요약을 마지막에 쓴다. 실행 시 사용한 명령은 `CUDA_VISIBLE_DEVICES='' python3 tools/workspace_python.py -m scripts.e2e.evaluate_map_town05_dev`이며 완료 결과가 남아 있는 상태에서 같은 명령을 재실행하면 의도적으로 거부한다. `scripts`는 `tools/workspace_python.py`가 구성하는 Python namespace이며 제거된 레거시 디렉터리 링크가 아니다.

CPU 2 thread로 240장×2모델 추론·집계에 **74.46초**가 걸렸고 GPU·SSH·CARLA 재실행·패키지 설치·새 학습은 없었다. 신규 평가기와 기존 Town06 평가기 단위검사 **10개 통과**(변경된 계획/감사 해시의 실패 종료 검사 포함). 저장한 NPZ와 CARLA 원본 semantic에서 **240장/보존 232장 양 모델 7×7 혼동행렬을 별도로 재계산해 정확히 일치**했다. 세 PNG도 원본 화각과 네 패널을 육안 확인했다. 이 DEV 비교는 한 후보의 교차-Town 경향을 찾은 것이며 추가 데이터와 보호 기준을 통과한 새 후보가 나올 때까지 채택 판단은 보류한다.
