## 화면 위치·RGB·원본 센서

위치는 원본 영상 좌표다. `near_ego`는 x=160–479, y=180–359이고, 하단 좌측 격자는 x=0–212, y=240–359다. 차선 픽셀 중 `near_ego` 비율은 Town01 **109,633/287,660 = 38.1%**, Town02 **41,669/108,805 = 38.3%**다. 하단 좌측 비율은 각각 **193,948/287,660 = 67.4%**, **76,009/108,805 = 69.9%**다. 이 고정 영역에서는 차선 위치가 크게 이동한 증거가 없다. 도로 `near_ego` 비율도 각각 56.3%와 56.7%다. 모든 3×3 영역의 원시 픽셀 수는 [감사기](../../../../../tools/e2e/audit_map_lane_train.py)의 JSON 출력에 있다.

차선 픽셀의 평균 RGB는 Town01 **(203.770, 128.142, 0.000)**, Town02 **(188.144, 111.950, 0.000)**이다. 정수 근사 명도 `(77R+150G+29B)//256`가 128–191인 차선 픽셀은 각각 **213,080/287,660 = 74.1%**, **59,281/108,805 = 54.5%**다. 도로 RGB 평균은 **(51.089, 51.278, 51.408)** 대 **(48.879, 49.066, 49.172)**다. 따라서 Town02 차선 색/밝기가 상대적으로 더 달라졌지만, 이 집계만으로 물체 재질·조명·노출 중 무엇이 원인인지 분리할 수 없다.

CARLA BGRA 광축 깊이를 동일하게 디코드하면 차선의 0.1–10m 픽셀은 Town01 **254,314/287,660 = 88.4%**, Town02 **97,150/108,805 = 89.3%**다. 두 그룹의 road/lane 깊이 무효 픽셀은 0이며, 원본 의미 태그 1·24가 패키지 road·lane에 정확히 대응한다. `other`의 원본 태그 구성은 다르다. 예를 들어 태그 3은 Town01 11,215,542픽셀, Town02 12,637,741픽셀이고, 태그 9는 각각 13,438,622와 5,206,145픽셀이다. 카메라 행렬의 **월드 z 좌표** 중앙값도 2.0361m와 2.2561m다. 이는 서로 다른 지도 지형 위의 월드 좌표이므로 카메라 장착 높이 차이라고 해석하지 않는다. 원본에는 모델 입력 외에 depth/pose가 있지만 두 모달리티를 학습에 제공했다는 뜻은 아니다.

## 다음 단일 요인 실험 제안 — 현재 미실행

고정 D1에서 차선이 희소해지고 기존 [A/B 결과](../map_road_lane_ab/README.md)의 Town05 DEV 차선 IoU가 9.01%→7.33%로 내려갔다. **가설:** 현 D0 기반 손실이 D1의 차선 픽셀에 주는 상대 신호가 부족하다. 검증 후보는 `semantic_loss`에 들어가는 7개 가중치 중 `lane_marking`(index 3)만 **정확히 2.0배**로 하는 것이다. 클래스 가중치 계산법, 나머지 여섯 가중치, 데이터 729장·순서·라벨, 모델, scratch 초기화, batch 8, 2,000 step, AdamW `3e-4`/`1e-4`, TRAIN crop과 seed별 RNG는 고정한다. D0 기준 가중치의 차선 항은 1.462326→2.924652가 된다. `semantic_loss`의 가중합 분모도 기존 식대로 같이 변하며, 이 후보의 D1 **원본 픽셀 기준** 차선 가중 비율은 2.136%→4.184%다. 실제 crop·gradient 영향과 IoU 개선은 아직 모른다. 이 숫자를 보고 1.5배/3배를 탐색하지 않는다.

실험을 실행한다면 먼저 코드·패키지 해시를 고정하고, 동일한 세 seed `20260922`, `20260923`, `20260924`에서 D1 기존 손실과 후보 손실을 짝지어 실행한다. 이전 D1 한 seed 결과는 재현 확인용으로만 둔다. 현재 학습기 SHA-256은 `ac3c71c071cc9db9f6b36fe0948ece9d034313c00853f986f843bb13a40e3c12`, 모델/손실 소스는 `1b0076c8f9d34192ab5aedf6cdf96ce2c14458e2bb49986685a6811376b0750b`, 클래스 가중치 소스는 `57c9392d8b700f5cf628865042b66ae630961f35fb8858a5d0ead77fe5a7c73b`다. 후보 구현은 학습 전에 별도 파일로 고정·해시를 기록해야 한다. 모델 출력 임계값이나 라벨은 바꾸지 않는다.

**현재 불변 입력으로 가능한 첫 판정:** Town01의 세 경로를 통째로 번갈아 제외한다. index `[0,114)`, `[114,301)`, `[301,497)`가 각각 기존 직진/p03/p01이며, Town02 index `[497,729)`는 매번 TRAIN에 남긴다. 각 fold에서 나머지 두 Town01 경로와 Town02로 두 손실을 같은 seed에 짝지어 학습하고 제외한 경로 전체를 평가한다. 누출을 막기 위해 기본 `sqrt_frequency` 가중치는 **그 fold의 학습용 Town01 두 경로만** 사용해 계산하고 두 팔에 동일하게 고정한다. 3 fold × 3 seed의 **9개 짝 모두** 차선 IoU 차이 **≥+5pp**, 도로 IoU 차이 **≥−1pp**여야 다음 단계로 간다. 7클래스 혼동행렬·IoU를 모두 공개한다. 이 판정은 전체 729장 D1의 기존 재현 계약과 다른 **내부 경로 holdout 탐색**이다. 프레임 랜덤 분할의 인접 영상 누출을 줄이지만 Town 밖 일반화는 검증하지 못한다. 이 문서에서 holdout 배열을 만들거나 학습하지 않았다.

**다음 외부 판정:** 경로 holdout을 통과한 동일한 2.0배 후보만 전체 D1으로 짝지어 학습한다. 이 단계의 기본 가중치는 기존처럼 전체 D0 TRAIN 497장으로 계산한다. **새롭게 확보해 수집 경로·배열 해시와 분할을 학습 전에 고정한 독립 DEV**에서 세 seed 모두 차선 IoU가 짝지은 기존 손실보다 **≥5pp**, 도로 IoU가 **≥−1pp**여야 한다. Town01 DEV에서는 기존 [A/B 사전 계약](../map_road_lane_ab/PLAN.md)의 도로 **≥97.751%**·차선 **≥89.233%** 및 7클래스 비퇴행 판정을 그대로 적용한다. 기존 Town05 DEV는 이 배율이나 중간 중단/선택 지표로 사용하지 않는다. 새 독립 DEV가 없으면 외부 성능 판정은 실행하지 않는다. 이전 Town05의 절대 도로 ≥80%·차선 ≥50%, D0 대비 각 +5pp라는 기존 최종 목표도 완화하지 않는다. 통과하더라도 별도 봉인 TEST·지도/주행 검증 전 모델 승격은 없다.
