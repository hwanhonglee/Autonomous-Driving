# Town05 지도 예측: 높은 확률의 오분류 확인

<!-- HH_260929 - Preserve a post-hoc repeated-DEV failure diagnosis without threshold selection. -->

**결론: 기존 신뢰도 0.5 필터로는 Town05의 주요 오분류가 제거되지 않는다.** [앞선 3프레임 투영 결과](../map_town05_projection_hardcase/README.md)에 저장된 예측 클래스와 최대 softmax 확률을 다시 읽었다. 모델 재추론이나 학습은 하지 않았다.

| 반복 DEV 프레임 | 도로→인도 오류: 전체 / 확률 ≥0.5 | 차선 누락: 전체 / 확률 ≥0.5 | 차선 누락 중 확률 ≥0.9 | 차선 누락 확률 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 0000 | 71,513 / 65,180 | 4,772 / 4,349 | 2,085 | 0.864 |
| 0115 | 33,587 / 27,696 | 11,177 / 10,648 | **6,934** | **0.951** |
| 0231 | 43,244 / 39,919 | 3,366 / 2,080 | 397 | 0.569 |

여기의 `확률 ≥0.5`는 **예측 점수 조건만** 통과했다는 뜻이다. 실제 지도 투영의 깊이·stride·위치 필터까지 통과했다는 수가 아니다. `≥0.9`는 높은 점수의 오류가 남는지 기술하려는 구간이며 새 운용 임계값이 아니다. 중앙값·90백분위수는 해당 오분류의 모든 픽셀에서 NumPy의 선형 분위수로 계산했다. 정확한 도로/차선, 도로→기둥, 전체 오류도 [결과 JSON](result.json)에 있다.

0115에서는 차선 정답 11,199픽셀 중 11,177픽셀이 다른 클래스로 나왔다. 그 잘못된 클래스의 점수 중앙값이 0.951인 반면, 맞게 예측한 차선 22픽셀의 점수 중앙값은 0.435였다. 따라서 현재 저장 예측에서 차선 누락의 주된 문제는 단순한 낮은 확률이 아니다. 이 수치로 새로운 임계값을 선택하면 이미 반복해 본 DEV에 맞춘 사후 조정이 된다.

진단 범위는 0000/0115/0231 **세 장의 전 시야 픽셀**이다. 원본 CARLA semantic은 정답 계산에만 썼고 예측은 기존 저장본 그대로다. [결과 JSON](result.json)은 원본 NPZ 3개, 저장 예측 NPZ 3개, 기존 투영 요약, 의미 라벨 변환 코드 및 이 감사 코드의 SHA-256을 기록한다. 원래 투영의 7×7 혼동행렬과 다시 계산한 행렬이 일치해야 결과를 쓴다. [감사 코드](../../../../../tools/e2e/audit_map_town05_confident_errors.py)의 경계 계산은 [단위 시험](../../../../../learning/tests/test_audit_map_town05_confident_errors.py) 1개로 확인했다.

이것은 실패를 본 뒤 수행한 **반복 DEV 사후 진단**이다. 모델 개선이나 독립 일반화 검증이 아니며 새 가중치, 임계값, 지도 승인, 주행 승격은 없다. 실제 성능 개선을 시험하려면 다른 외관의 허용 TRAIN 원본과 미사용 DEV를 먼저 확보해 역할과 기준을 고정해야 한다. 특히 Town05처럼 어두운 포장면과 회색 차선이 있는 TRAIN 짝을 수집할 수 있어야 한다.
