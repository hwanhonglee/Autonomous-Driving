# Town05 어두운 노면에서 드러난 지도 예측 오류

<!-- HH_260929 - Preserve a fixed repeated-DEV hard-case without model promotion or new independent validation claims. -->

**결론: Town05_Opt의 어두운 도로·회색 차선 장면에서 예측 오류가 나타나 지도 누적까지 크게 틀어졌다.** 같은 AI v2, 같은 깊이·위치, 같은 임계값으로 Town05 반복 DEV 원본 3장을 재생했다. 원본/코드/출력 해시와 저장 예측에서의 독립 재투영은 통과했지만, 세 장 모두 [기존 Town05 절대 목표](../map_road_lane_ab/README.md)인 도로 ≥80%·차선 ≥50%에 미달한다. 이 3장 검사는 별도의 승격 관문은 아니다. 새 가중치를 학습하거나 TEST를 열지 않았다.

| 고정 표본 | 도로 픽셀 IoU | 차선 픽셀 IoU | 신호등 기구 픽셀 IoU | 기준 누적 cell | 모델 누적 cell |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0000 | 28.21% | 5.63% | 17.93% | 3,529 | 2,646 |
| 0115 | 50.43% | **0.19%** | 1.29% | 8,187 | 6,983 |
| 0231 | 40.66% | 17.57% | 1.35% | 12,176 | 10,075 |

중간 0115에서는 정답 차선 **11,199픽셀 중 22픽셀만 차선으로 예측**했다. 첫 프레임은 정답 도로 114,414픽셀 중 **71,513픽셀을 인도**로 예측했다. 마지막 누적 지도에서 공통 관측 격자는 9,148/합집합 13,103(**69.82%**), 공통 격자의 우세 라벨 일치율은 **50.49%**다. 우세 라벨별 셀 수는 도로 **8,581(기준) 대 5,714(모델)**, 차선 **630 대 131**, 기둥 **167 대 940**이었다. 동일 좌표로 실제 양쪽 모두 관측한 기준 도로 7,828셀 중 2,864셀은 모델이 인도, 594셀은 기둥으로 분류했다. 기준 차선 630셀 중 모델이 같은 좌표에 증거를 남기지 못한 곳이 272셀이고, 공통 358셀 중 차선으로 일치한 곳은 92셀뿐이다. 이는 연속 맵의 면적이나 구조물 검출률이 아니라 **3개 건너뛴 표본의 희소 격자**다.

## 해석과 다음 학습 조건

이 비교는 [Town01 3프레임 배선](../map_learned_projection_bridge/README.md)의 높은 수치를 다른 Town의 성능이라고 착각하지 않기 위해 수행했다. Town01 3장 중 2장은 모델 TRAIN에 정확히 포함됐고, Town05는 이미 여러 번 본 **탐색 DEV**다. 두 표본 집합은 독립 A/B가 아니므로 수치 차이만으로 원인을 단정할 수 없다. 다만 [RGB 분포 감사](../map_road_lane_ab/APPEARANCE_SHIFT.md)의 밝기·차선 색 차이, [사진측광 A/B 실패](../map_photometric_pilot/README.md)의 Town01 퇴행, 이번 Town05 누적 오류는 **새 외관을 가진 허용 TRAIN 자료와 미사용 DEV**를 확보한 다음 개선을 시험해야 함을 뒷받침한다.

| 서로 다른 역할의 3장 진단 | 도로 IoU 범위 | 차선 IoU 범위 | 공통 격자 우세 라벨 일치 |
| --- | ---: | ---: | ---: |
| Town01, 학습 노출 경로 | 95.93–99.69% | 85.71–96.92% | 97.99% |
| Town05_Opt, 반복 탐색 DEV | 28.21–50.43% | 0.19–17.57% | 50.49% |

이 표는 **역할·경로·표본이 다른 두 배선 결과의 대비**이며 새 일반화 점수나 통계적으로 독립된 A/B가 아니다.

다음에는 Town05 DEV에 맞춰 threshold나 증강 강도를 다시 고르지 않는다. [C-track 촬영 사전 점검](../map_ctrack_capture_readiness/README.md)에 따라 새 직진·회전 **TRAIN** 쌍을 안전하게 얻고, 별도 미사용 DEV를 보호·선언한 뒤 한 번의 고정 A/B 학습을 해야 한다. 새 DEV와 라벨/렌더 QA 없이 이 결과로 모델을 채택하거나 주행 모델에 연결하지 않는다. 신호등 *상태*, 횡단보도 연결, 차선 규칙, 실제 센서 깊이/측위, Lanelet2·HD-map, 10Hz 전체 처리도 이번 대상이 아니다.

## 재현성과 안전 경계

- [사전 고정 계약](PLAN.md)은 원본 240장 중 **0000/0115/0231**, RGB/semantic/depth/pose 입력 및 각 SHA, AI v2 checkpoint와 투영 임계값을 실행 전에 고정했다. 파일명에 `training`이 있어도 source의 실제 역할은 반복 DEV다. 3장 사이의 **237장**을 누적한 척하지 않는다.
- [실행 요약](run_v1/summary.json)에는 7클래스 혼동행렬, 각 샘플 픽셀 IoU, CPU 추론시간(약 0.09–0.13초/장), 두 격자 관측 셀과 8개 출력 파일의 SHA-256을 저장했다. [모델 격자](run_v1/learned_evidence.json)와 [기준 격자](run_v1/oracle_evidence.json)는 분리했고, 정확한 [예측 클래스+확률](run_v1/frame_0115_prediction.npz)도 저장했다.
- `python3 tools/workspace_python.py tools/e2e/verify_town05_projection_hardcase.py`는 사이트 원장의 *반복 탐색 DEV만 허용* 상태를 재검사하고, 모델을 재추론하지 않고 저장 예측·원본 깊이/위치에서 **3개 혼동행렬·두 격자 스냅샷·출력 SHA·차량 중심 좌표**를 재계산해 `VERIFIED_REPEATED_DEV_THREE_FRAME_DIAGNOSTIC`으로 통과했다. 로컬 CPU 2스레드만 사용했고 GPU·CARLA·Autoware·SSH·설치는 사용하지 않았다.
