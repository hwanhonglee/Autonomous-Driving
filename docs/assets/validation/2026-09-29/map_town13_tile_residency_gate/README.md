## What the existing API proves

| Candidate observation | Source evidence | Why it is not a tile-residency certificate |
| --- | --- | --- |
| `world.get_settings().spectator_as_ego`, spectator transform, successful ticks | `CarlaServer.cpp` 539–557; `LargeMapManager.cpp` 1122–1134, 710–727 | The setting enrolls the spectator as a streaming source only when no other actor is considered; a tick does not return the target tile's state. |
| `ALargeMapManager::IsTileLoaded(location)` / `CurrentTilesLoaded` | `LargeMapManager.h` 127–140; `.cpp` 976–1017 | This set is updated immediately after *requesting* streaming. It can say true before the level is loaded and visible. It is not exposed by the Python API. |
| `IsLevelOfTileLoaded(tile_id)` | `LargeMapManager.cpp` 509–526 | This checks `GetLoadedLevel()` but not visibility or pending transition, and is only Blueprint callable, not a Python/RPC query. UE4's `ULevelStreaming::IsLevelVisible()` checks the loaded level's `bIsVisible`; `IsStreamingStatePending()` reports an incomplete transition (`LevelStreaming.cpp` 1280–1304). |
| `world.get_level_bbs`, `get_environment_objects`, ray/project queries | `PythonAPI/carla/source/libcarla/World.cpp` 340–345; `CarlaServer.cpp` 579–620, 2565–2600 | These observe scene geometry or collision, not the manager's target tile identity and actual visibility. A hit can come from other content; a miss is inconclusive. `cast_ray` also computes origin-adjusted endpoints but passes the original endpoints to `URayTracer::CastRay` (2592–2598), so it is especially unsuitable after a world-origin rebase. |
| `OnLevelAddedToWorld` and screen tile counts | `LargeMapManager.cpp` 137–143, 1068–1085 | The log does not name the tile or camera target. The displayed loaded count comes from `CurrentTilesLoaded`, the requested-state set. |

The Python `World` binding at `World.cpp` 309–346 has no tile-state call. The C++ batch `ConsoleCommand` variant is not exported in `PythonAPI/carla/source/libcarla/Commands.cpp` 62–253, and `IsLevelOfTileLoaded` is not a console `Exec` command. There is therefore no **provable, no-sensor target-tile preflight** through this installed Python egg. Geometry-only observation may help diagnosis, but it must not turn a camera owner green.

## Minimal source patch proposal

Add one **read-only, synchronous** `get_large_map_tile_state(global_location)` RPC and expose it as `world.get_large_map_tile_state(location)` in the source Python egg. The server implementation should run on the game thread, convert the CARLA location from metres to global UE centimetres, and use `ALargeMapManager::GetTileID` and `MapTiles.Find` for the *exact* requested location. It should return explicit fields, not one optimistic boolean:

```text
episode_id, server_frame, queried_global_location_cm, current_origin_cm,
tile_x, tile_y, tile_exists, selected_in_CurrentTilesLoaded,
level_loaded, level_visible, streaming_state_pending,
spectator_is_streaming_source, spectator_global_location_cm
```

The manager can compute `level_loaded`, `level_visible`, and `streaming_state_pending` from that tile's `ULevelStreamingDynamic` using UE4's `IsLevelLoaded()`, `IsLevelVisible()`, and `IsStreamingStatePending()`. It must report `tile_exists=false` when `MapTiles.Find` fails, without dereferencing a missing entry. The server should also report that `SpectatorAsEgo && ActorsToConsider.Contains(Spectator)` and convert the spectator's local position through `LocalToGlobalLocation`; `spectator_as_ego=true` in settings alone is insufficient. The typed RPC response and Python binding would touch `LargeMapManager.h/.cpp`, `CarlaServer.cpp`, a new `LibCarla/source/carla/rpc` result type, `LibCarla` client/detail and `World` forwarding, and `PythonAPI/carla/source/libcarla/World.cpp`. Keep this as a separate source build and pin the rebuilt editor plus matching egg before any owned launch. No such patch has been applied or compiled here.

The owner may spawn a camera **only** if a same-episode, same-target query after spectator relocation and settling ticks reports: target pose equals spectator global pose within the predeclared tolerance; tile exists; selected, loaded, and visible are all true; streaming transition is not pending; spectator is the streaming source; and the world map is the pinned full Town13 asset. Requery immediately before spawn with no intervening world tick or actor movement. Fail closed on RPC timeout, missing field, changed episode/frame/pose, extra vehicle or sensor, or any false readiness bit. The response is a pre-spawn certificate, not proof that rendering will be correct or that the tile will stay resident if the streaming source later moves.

The crash path needs a **separate defensive source fix** before relying on camera cleanup: `FActorSensorData::RecordActorData` moves the stream (`ActorData.cpp` 252–257), then `FCarlaActor::PutActorToSleep` destroys the sensor (`CarlaActor.cpp` 154–162), whose `ASensor::EndPlay` calls `Stream.GetToken()` (`Sensor.cpp` 113–121). `FDataStreamTmpl::IsStreamReady()` checks only that its outer `boost::optional` is engaged (`DataStream.h` 46–56); after a move, the optional may still contain a moved-from `Stream` whose `_shared_state` is null (`streaming/detail/Stream.h` 34–36, 77–79). A guard using only `IsStreamReady()` is therefore insufficient. A source fix should explicitly empty the moved-from `FDataStream` in `ASensor::MoveDataStream()` and have `EndPlay` skip `GetToken`/`CloseStream` when no stream remains, while still deregistering the sensor. Test ordinary destroy and sleep/wake paths with a real source build. This crash fix does not substitute for tile readiness.
