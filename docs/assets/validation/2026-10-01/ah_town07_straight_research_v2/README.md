# 주행 모델이 중간에 멈춘 이유 — 실제 제어 재현

<!-- HH_261001 - Explain the measured receding-horizon stall separately from infrastructure and safety approval. -->

**결론: 차로를 따라 조금 주행했지만 계속 주행하지 못했다. 모델이 바로 실행할 속도를 0으로 예측해 스스로 멈췄다.** 이 시험은 성공 주행 영상이 아니라 개선할 실패를 재현한 기록이다.

## 누가 운전했나

CARLA Town07의 기존 학습 경로에서 6카메라와 차량 상태를 실제 AH 모델에 넣었다. 모델이 선택한 궤적·속도를 외부 추종 제어기가 조향·가속·제동 명령으로 바꿨다. 초기 센서 이력과 출발을 확보한 전문가 명령 11개 이후 **모델 추종기 명령 366개**가 실제 적용 ACK를 받았다. 전문가의 비교용 명령도 별도로 저장했지만 이후 실제 운전 명령으로 대신 쓰지 않았다.

9km/h 제한의 20초 진단이다. 30km/h 검증, Autoware 통합 주행, 독립 미학습 경로 시험, 전체 경로 완료가 아니다.

| 확인 항목 | 실제 결과 |
| --- | --- |
| 상태 / 6카메라 묶음 | 400개 / 200개, 영상 총 1,200장 |
| 모델 실제 명령 | 366개 ACK, 그중 다음 상태까지 정렬 검증 가능한 것은 365개 |
| 진행 거리 / 최고 속도 | 15.22m / 8.38km/h |
| 최대 경로 중심 오차 | 0.046m — 전체 차체 차로 포함 검사와는 다름 |
| 충돌 / 차선 침범 센서 이벤트 | 0 / 0 |
| 정지 상태로 끝난 구간 | 약 9.25초 |
| 추론 183회 p50 / p95 / 최대 | 26.39 / 31.90 / 41.45ms |
| 실행 소스 / 종료·포트 | 해시 일치 / 정상 정리 |
| 목표 도달 / 기능 승인 | 아니오 / 0개 |

첫 시험은 실행 중 최종 기록 코드 변경을 감지한 owner 실패가 있었다. 이 두 번째 시험은 코드를 고정했고 그 문제 없이 정지가 다시 나타났다. 원래 수집기의 20초 제한 종료 오류도 지우지 않았다. 추가 결과의 `DIAGNOSTIC_BUDGET_REACHED`는 **예정한 진단 시간 종료**라는 뜻이며 주행 성공 판정이 아니다.

## 왜 멈췄나 — 현재 직접 확인된 것

정지한 시점에 모델이 고른 속도는 다음과 같았다.

| 지금으로부터 | 0.1초 | 0.3초 | 0.5초 | 1초 | 2초 | 6.4초 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 목표 속도 m/s | 0 | 0 | 0 | 0.018 | 0.558 | 8.333 |

제어기는 가까운 **0.3초 목표**를 실행한다. 그런데 매번 새로 추론할 때마다 “지금은 0, 나중에는 가속”을 다시 예측하므로, 실제로는 그 나중에 도달하지 못하고 정지한다. 비교용 전문가는 계속 가속을 제안했고, 독립 긴급 제동 개입은 없었다.

모델이 왜 이런 속도 모양을 배웠는지는 TRAIN 자료의 출발·저속·정지 분포와 손실/기울기를 확인 중이다. 단순히 CPU가 느려서 멈춘 것이라는 해석은 이번 183회 추론 시간과 맞지 않는다. 반대로 이번 추론 시간만으로 모든 입력·통신·제어를 포함한 10Hz 실시간성을 인증하지도 않는다.
