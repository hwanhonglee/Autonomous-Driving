# 지도 모델: 같은 데이터와 학습량에서 실제 개선

<!-- HH_261001 - Report paired training gains without claiming unseen-map or runtime readiness. -->

결론: **문맥을 넓힌 B 모델이 기존 구조 A보다 두 평가 경로의 7개 항목 모두 높았다.** 이전 기준 모델 대비 비교 조건 5개도 통과했다. 다만 아직 모든 지도에서 잘 되는 모델이나 완성된 정밀지도 생성기는 아니다.

## 무엇을 바꾸고 학습했나

기존 모델은 영상에서 도로·차선·보도·기둥·신호등 구조물·표지판·기타를 구분한다. B에는 주변을 더 넓게 보는 작은 합성곱 가지를 추가했다. 새 가지의 초기 출력을 0으로 만들어, 학습 전에는 기존 가중치의 결과와 정확히 같도록 했다. 기능별 헤드를 무작정 늘린 실험은 아니다.

- A: 기존 구조 130,503개 파라미터. B: 넓은 문맥 구조 245,831개 파라미터.
- 같은 부모 가중치, 같은 TRAIN 729장, 같은 입력 순서·증강·시드·배치 크기 8.
- 각각 **추가 10,000 step**. 부모의 2,000 step을 포함하면 각각 누적 12,000 step이다.
- PRO6000 **물리 GPU 0**, 개인 venv에서 실제 학습. A 382.57초, B 401.48초, 합계 **13분 4초**. 평가·전송·검산 시간은 별도.
- 두 최종 가중치를 저장한 다음에 평가했다. 중간 평가 점수로 체크포인트를 고르지 않았다.
- [실행 전 고정 계획](PLAN.md), [소스·데이터 고정 기록](bundle.json).

## 같은 추가 학습량으로 비교한 결과

아래는 IoU(예측 영역과 정답 영역의 겹침 비율, 높을수록 좋음)다. A/B 모두 이번에 학습한 모델이다. 아래 A를 이전 기준 모델과 혼동하지 않는다.

| 항목 | Town01 A | Town01 B | Town02 p02 A | Town02 p02 B |
| --- | ---: | ---: | ---: | ---: |
| 도로 | 99.23% | **99.67%** | 95.42% | **98.66%** |
| 차선 표시 | 95.56% | **95.85%** | 96.90% | **98.10%** |
| 보도 | 94.71% | **96.95%** | 85.65% | **92.62%** |
| 기둥 | 30.23% | **40.81%** | 30.27% | **43.82%** |
| 신호등 구조물 | 18.24% | **38.21%** | 32.71% | **39.23%** |
| 교통 표지판 | 5.59% | **6.77%** | 62.89% | **76.39%** |
| 기타 | 96.07% | **97.50%** | 91.64% | **95.09%** |

이전 기준 모델의 차선 점수는 Town01 91.23%, p02 92.07%였다. 이번 B는 각각 **+4.61%p, +6.02%p**다. 그중 모델 구조의 효과는 같은 추가 학습량의 A와 비교해야 하며, 그 차이는 각각 **+0.29%p, +1.20%p**다. 학습량 증가 효과와 구조 변경 효과를 합쳐서 전부 구조 덕분이라고 하지 않는다.

## 결과를 어떻게 확인했나

1. 두 모델 × (Town01 118장 + p02 232장) = **700개 예측**의 전체 픽셀을 다시 집계했다. 저장된 혼동행렬과 정확히 일치했다. [검산 결과](audit.json).
2. 실제 최종 가중치를 안전한 NPZ로 불러와 로컬 CPU에서 같은 **700장 모두 재추론**했다. GPU 결과와 픽셀 일치율은 99.9885~99.9964%, 클래스 IoU 최대 차이는 0.108%p였다. 사전 수치 허용 범위를 통과했다. [CPU 가중치 검산](cpu_verification.json).
3. 첫 장·중간 장·마지막 장을 고정해서 전체 화각 비교 PNG와 GIF를 만들었다. 점수가 좋은 장면만 고르지 않았다.

## 아직 부족한 부분과 다음 실험

- Town01 표지판 **6.77%**, 신호등 구조물 **38.21%**는 충분하지 않다. 특히 신호등 구조물 분할은 빨강/초록 신호 상태 인식과 다르다.
- Town01은 알려진 평가 경로, p02도 과거 결과를 본 내부 holdout이다. **독립된 새 지도 일반화 성공으로 세지 않는다.**
- CPU 2스레드 실측 B p95는 Town01 161.59ms, p02 183.88ms다. **로컬 CPU 지도 추론은 아직 10Hz를 충족하지 못한다.** 이는 주행 AH 모델의 추론 시간과 다른 측정이다.
- C-track에서 정상 조명 RGB와 복구된 정답을 연속 수집하여, 가중치를 고정한 외부 지도 진단을 한다. 이번 비교에 쓰는 C-track 데이터는 TRAIN에 넣지 않는다.
- 이후 부족한 작은 객체 데이터·다른 날씨/지도 검증, 속도 최적화, 깊이·자세를 이용한 지도 누적/벡터화·연결성 검증이 남아 있다. 이번 결과만으로 자동 지도 생성 전체나 주행 기능 완료를 선언하지 않는다.
