# 새 주행 V2 — 실제 200회 학습, 속도 출력 개선·회전 형상 미달

<!-- HH_261001 - Explain real weight updates separately from complete driving training and approval. -->

기존 W1을 다시 튜닝한 것이 아니라, **새 공간·시간 모델을 만들고 원격 GPU 0에서 실제 역전파와 가중치 업데이트 200회를 완료했다.** 속도 출력은 학습됐지만 회전 형상의 평균 손실은 악화됐다. 이번 체크포인트를 차량 제어에 연결하거나 기존 모델 대신 채택하지 않았다. 현재 학습은 종료됐다.

## 무엇을 만들었나

기존 한 시점 중심 구조와 별도로, −0.8/−0.6/−0.4/−0.2/0초의 실제 6카메라 영상과 차량 이동·상태·내비게이션을 받는 모델을 구현했다. 영상의 위치별 특징을 유지하며, 한 개의 공간 경로를 위한 33개 곡률과 선호 속도를 출력한다. 파라미터는 **2,729,703개**다. 현재 밀집 중심선 내비게이션을 쓰므로 무지도 주행 모델이라고 부르지 않는다.

과거가 없는 곳은 현재 영상을 복제하지 않고 마스크한다. 공간 정답도 기록된 미래 거리까지만 사용한다. 기록에 없는 64m 경로를 만들어 채우지 않으며 기존 30km/h 정답을 저속 정답으로 잘라 바꾸지 않았다.

별도로 저속 경로/시간 계산부와 손실을 구현했다. 계산부는 관측된 초기 속도를 보존하고 연속 가감속·정차를 계산한다. **현재 계산부의 운용 상한은 2.5m/s다.** 기존 자료 2,787개 중 현재 속도와 전체 6.4초 미래가 이 상한에 들어오는 이동 표본은 단 1개였다. 따라서 이번 학습에는 계산부 이후의 시간별 궤적 손실을 쓰지 않았다. 경로 모양·선호 속도의 **제한 전 출력만 학습한 진단**이다. 의미가 검증된 정지 이유가 없어 정지 의도·정차 거리도 학습하지 않았다.

코드는 [모델](../../../../../learning/portable_e2e/temporal_model_v2.py), [시간 영상 어댑터](../../../../../learning/portable_e2e/temporal_dataset_v2.py), [저속 계산부](../../../../../learning/portable_e2e/path_time_decoder_v2.py), [손실](../../../../../learning/portable_e2e/temporal_losses_v2.py), [학습 실행기](../../../../../tools/e2e/train_temporal_v2_raw_bootstrap_20261001.py)에 있다. 기존 모델·손실·계약과 기존 체크포인트는 변경하지 않았다.

## 학습과 결과

| 항목 | 실제 실행 |
| --- | --- |
| 환경 | SSH PRO6000의 기존 개인 `venvs/py312`; 물리 GPU 0만 사용 |
| 학습 자료 | 기존 K1 2,787개/8 episode; 이동·공간 정답 조건을 만족한 2,487개가 후보 |
| 초기화 | 새 무작위 가중치; W1 이어 학습 아님 |
| 설정 | AdamW, 학습률 0.0001, batch 2, seed 20261001, 기울기 제한 5 |
| 실제 양 | 200 optimizer 업데이트, 중복 없는 400개 앵커, 8 episode; 후보의 16.08% |
| 시간·메모리 | 학습 루프 33.89초, step 평균 169.45ms, p95 177.45ms; Torch 최대 할당 약 842MiB |
| 평가 범위 | 이전에 사용한 DEV의 사전 고정 8개 표본/2 episode. 새 독립 검증이나 봉인 TEST 아님 |

다음은 같은 8개 표본을 새 가중치 전후에 평가한 평균이다. **모두 SmoothL1 손실이며 실제 궤적 거리 오차나 주행 성공률이 아니다.** 곡률은 0.1로 정규화돼 있다.

| 평가 항목 | 학습 전 | 200회 후 | 판정 |
| --- | ---: | ---: | --- |
| 공간 곡률 | 0.080065 | 0.086137 | **7.58% 악화**, 8개 중 6개 악화 |
| 선호 속도 | 5.450575 | 0.254748 | 95.33% 감소, 8개 모두 감소 |
| 합산 손실 | 5.470591 | 0.276283 | 감소했지만 회전 개선의 증거는 아님 |

이 실행의 합산은 `0.25 × 곡률 손실 + 속도 손실`이다. 초기 합산의 99.63%가 속도 손실이라, 속도 개선이 곡률 악화를 가렸다. 새로운 구조가 가중치를 학습한다는 점은 확인했지만 **회전 성능이 나왔다고 볼 수 없다.**

![고정 표본의 곡률·속도 손실을 분리한 비교](known_dev_tasks_before_after.png)

[200개 실제 업데이트의 항목별 곡선](raw_training_tasks.png)은 서로 다른 미니배치의 값이다. 마지막 미니배치 손실만으로 수렴을 판단하지 않는다.

학습 후보의 현재 명령은 직진/차로 추종 2,445개·좌회전 24개·우회전 18개다. **98.31%가 직진 명령**이다. 이는 현재 명령 기준이며, 직진 명령이 나온 표본의 미래 경로에 회전이 전혀 없다는 뜻은 아니다. 다음에는 미래 경로의 실제 회전량·속도·출발/회복 구간까지 함께 조사해 균형을 선언하고, 형상과 속도의 손실 및 검증값을 따로 보고해야 한다.

추가로 원격 CPU에서 **실제 미래 정답의 방향 변화도 전량 조사했다.** 6.4초 동안 상대 방향이 10도 이상 바뀌는지를 진단용 기준으로 나눴다.

| 자료 | 작은 방향 변화 | 왼쪽 굽이 | 오른쪽 굽이 |
| --- | ---: | ---: | ---: |
| 후보 2,487개 | 2,185 | 70 | 232 |
| 실제 학습한 400개 | 346 | 11 | 43 |

실제 학습의 13.5%에는 이 기준의 굽이가 들어 있었다. 따라서 “98% 현재 명령이 직진”을 “98% 미래 경로가 직선”이나 곡률 악화의 확정 원인으로 바꾸면 안 된다. 왼쪽 굽이 자료와 전체량은 부족하며, 목적함수·표현·학습량을 별도로 비교해야 한다. [분포와 원본 해시](../../../../../storage/experiments/training/2026-10-01/temporal_v2_raw_bootstrap_v1/future_shape_inventory.json)를 보존했다. 미래 정답을 추론 입력에 추가하지 않았다.

## 로컬에서 바로 10Hz로 되나

**아직 아니다.** 현재 로컬 `/usr/bin/python3`의 Torch 1.8.0a0는 CPU 전용이며 CUDA 빌드가 없다. RTX 3090 Ti가 있다는 사실만으로 이 Torch가 GPU를 사용할 수는 없다. 새 패키지를 설치하지 않았으며 GPU 측정 거부 기록을 보존했다.

완료된 체크포인트를 로컬 CPU 1 thread에서 실제 과거 30장 입력으로 측정했다. 10회 준비 후 30회씩 측정한 평균/p95는 다음과 같다.

| 측정 범위 | 평균 | p95 |
| --- | ---: | ---: |
| 이미 준비된 5시점 입력 → 제한 전 신경망 출력 | 183.93ms | 185.17ms |
| 같은 저장 앵커의 이미지 해시·JPEG 해독·텐서 구성 → 신경망 출력 | 271.54ms | 276.80ms |

저장소 캐시가 따뜻한 동일 표본 반복이다. 실시간 센서 수신, 시간 계산부, 제어 명령·ACK, Autoware는 제외했다. GPU 학습 step 시간도 주행 추론 FPS로 환산하지 않는다.

### 실제 연속 입력에서 과거 CNN 특징 재사용

<!-- HH_261001 - Report the real learned-checkpoint stream separately from synthetic timing tests. -->

[별도 특징 캐시](../../../../../learning/portable_e2e/temporal_cached_encoder_v2.py)를 구현했다. 학습 파라미터와 체크포인트 구조는 바꾸지 않고 추론에만 적용한다. 카메라 파일 해시와 실제 정규화 픽셀·모델 가중치 내용을 검사하며 episode/split/rig/시계/가중치가 바뀌면 재설정한다. 과거 시점은0.2초 간격이고 입력은0.1초마다 오므로 두 교차 시점 열을 위한 최대9개 카메라 묶음을 유지한다.

완료된 체크포인트와 실제 Town07 연속40개 앵커를 CPU1thread에서 같은 입력으로 대조했다. 첫두 입력은 각각30장 계산, 이후38입력은 새6장만 계산한다. 모든 제한전 출력은 선언한 `atol=1e−6, rtol=1e−6` 비교에 통과했다. 최대 절대 차이는1.907e−6으로 비트 단위 동일은 아니며, 속도값 크기에 따른 상대 허용오차를 포함한다.

| 같은 실제 연속38입력의 측정 범위 | 평균 | p95 |
| --- | ---: | ---: |
| 전체 과거창 신경망 재계산 | 203.00ms | 209.16ms |
| 과거 특징 재사용, 출처·픽셀·가중치 검사 포함 | **60.98ms** | **65.82ms** |
| 원래 저장영상 해시/해독/텐서 구성 + 특징 재사용 | 128.92ms | 133.90ms |

**이 단계에서는 신경망 계산이 약 70% 줄었지만 원래 저장영상 처리까지 포함하면 100ms를 넘었다.** 이어서 이전 영상의 검증된 정규화 텐서를 재사용하는 어댑터까지 검증했다. 결과는 다음 절에 있다. 실시간 센서·시간 계산부·제어/ACK·Autoware는 제외돼 있으므로 10Hz 폐루프 합격은 아니다. [40개 입력의 개별 시간·CNN 계산량·출력 차이](../../../../../storage/experiments/training/2026-10-01/temporal_v2_raw_bootstrap_v1/local_cpu_cached_stream_profile.json)와 [측정 실행기](../../../../../tools/e2e/profile_temporal_v2_cached_stream_20261001.py)를 보존했다.

### 이어 완료한 영상 해독 캐시 — 계산 범위 평균86ms

<!-- HH_261001 - Keep the complete calculated input path and unmeasured vehicle pipeline distinct. -->

[새 영상 어댑터](../../../../../learning/portable_e2e/temporal_decoded_cache_v2.py)까지 구현하고 **같은40개 실제 연속앵커**로 다시 측정했다. 현재6장은 새로 해독하고 과거24장은 정규화 텐서를 재사용한다. 재사용 때도 원본파일을 읽어SHA256을 매번 확인하며, 모델 입력의 모든 텐서는 원래 어댑터와 **정확히 같았다.** 모델 출력은 앞의 절대/상대오차 기준에 통과했다. 캐시는 최대54장, 실제최대35.60MiB였고 다른episode/rig/출처/시계/설정과 파일변경을 검사했다.

첫두30장처리 뒤38개 정상상태 입력의 결과:

| 실제 측정 범위 | 평균 | p95 |
| --- | ---: | ---: |
| 매접근파일검증 + 해독결과재사용 + 텐서구성 | 24.50ms | 27.51ms |
| 과거CNN특징재사용 + 신경망출력 | 61.20ms | 66.22ms |
| 두단계합계, 출처구성 포함 | **85.86ms** | **92.64ms** |

같은 앵커의 앞선 무캐시 입력 처리+전체 신경망 측정 합계는 평균 270.94ms였다. 별도 실행한 측정이므로 CPU 상태 차이와 작은 표본의 한계를 유지한다. 두 캐시는 가중치나 정답을 바꾸지 않는 처리 개선이다.

**측정 범위는 100ms 안에 들어왔지만 실제 센서→제어→ACK/Autoware까지 10Hz로 주행했다는 뜻은 아니다.** 첫 두 호출의 초기 준비 지연과 rig/시계 전환 후 재설정도 따로 측정해야 한다. ## 다음 학습으로 가기 전에 남은 일

1. **데이터 균형:** 위 전량 조사 결과를 바탕으로 직진·좌/우회전·저속 회복의 균형을 선언하고, 훈련/새 DEV/TEST의 독립 장소를 먼저 고정한다. 같은 327개 겹치는 창을 독립 주행 327회로 세지 않는다.
2. **저속 정답:** [이번 V4 수집 결과](../town07_low_speed_moving_v4_results/README.md)의 40–120m 순항 외에, 이미 전문가 예비 주행이 가능했던 10–30m 구간을 6카메라·미래 기록으로 새로 수집한다. V4는 현재 학습에 편입하지 않았다.
3. **학습 목적 연결:** 적격 저속 자료로 경로→시간 계산부 이후 XY·속도·초기 가감속을 함께 감독한다. 정지/출발 의미 라벨을 검증한 뒤 관련 손실을 활성화한다.
4. **지연 및 호환성:** 과거 특징 재사용, 현재 영상 baseline 대조, 데이터 ±1ms와 모델 ±3µs의 시간 허용 범위 차이를 별도 revision에서 정리한다. 이번 정확한 CARLA 시계 표본은 모델 입력 검사에 통과했지만 일반적인 jitter 입력까지 호환된다는 뜻은 아니다.
5. **본 학습·주행:** [재설계의 30 episode 이상 본 학습 계획](../../../../portable-e2e-redesign-2026-10-01.md)을 자료·독립 검증·목표 손실과 연결해 실행한다. 200회 진단은 이 계획의 대체물이 아니다. 실제 차량 조종과 차체/제어/지연 검증까지 통과해야 기능 승인으로 센다.

현재 9개 상위 영역/30개 하위 기능 중 승인 수는 **0/30**, 우선 복구 대상은 직진·좌회전·우회전·목표속도 추종·종점 정지의 5개다. 지도 모델은 별도이며 이번 블록에서는 가중치를 업데이트하지 않았다. 다른 설치 환경의 패키지·GPU 1·기존 체크포인트·원본 자료에는 손대지 않았다.
