# 45초 직진 3회 — 2회 통과, 1회 불필요한 정지 명령

<!-- HH_261001 - Explain every predeclared repetition, including the failed moving-speed prediction. -->

**PI 제어로 주행은 개선됐지만, 세 번 모두 안정적으로 주행하지는 못했다.** 같은 W1 모델·같은 Town07 직진 경로·같은 PI 설정을 총 45초씩 3회 실행했다. 처음 두 번은 사전에 정한 15개 검사를 모두 통과했다. 세 번째에서는 움직이는 경로 후보가 목표속도 0을 내놓아 정지 명령이 발생했다. 따라서 반복 시험 전체는 **재현성 미달**이다.

좋은 두 번만 골라 성공이라고 하지 않는다. 세 실행의 원자료, 실패, 화면을 모두 아래에 남겼다.

## 실제로 얼마나 주행했나

각 45초 중 짧은 전문가 출발을 공개하고, 이후 약 43.2초는 학습 모델의 경로·속도를 추종했다. 속도 상한은 2.5m/s, 약 9km/h다. 표의 거리는 명령 수신 확인 이후 실제 차량 위치를 원래 경로에 독립적으로 투영한 값이다.

차체 900개와 두 관측 사이의 이동 영역 899개를 각각 검사했다. 이 검사는 기록 사이의 제한된 선형 이동 영역이며 모든 연속 물리 충돌을 증명하는 검사는 아니다. 전체 명령과 held tick의 수신 확인 대조, 입력·출력 해시, 실행 소스와 종료 후 원래 TCP/UDP 포트 검사도 세 번 모두 통과했다.

## 세 번째가 실패한 이유

**PI가 정지 신호를 만든 것이 아니라, 모델의 움직이는 후보가 목표속도 0을 예측했다.** 독립 검산에서 34개는 새 신경망 예측 17개와 그 명령을 유지한 17개였다. 별도의 STOP 후보군을 선택한 경우는 0개였다. 움직이는 후보 1·3·4의 속도 배열에서 문제가 발생했다.

첫 예측은 학습 제어 시작 약 2.7초 뒤, 마지막은 약 10.35초 뒤였다. 다섯 정지 명령 구간을 합치면 1.70초지만, 차량이 실제로 연속 정지한 최장 관측은 0.60초다. **명령 시간과 실제 정지 시간을 같은 값으로 쓰지 않는다.** 경로·속도를 임의로 바꾸거나 정지 명령을 무시해 통과시키지 않았다.

PI 제어는 속도 오차를 누적해 페달을 조정하는 개선이다. 모델이 목표속도를 0으로 정하면 원래 정지 분기를 유지해야 한다. 따라서 이 결과는 제어 개선만으로 모델의 잘못된 속도 예측까지 해결할 수 없음을 보여준다.

## 전체 목표에서는 어디까지 왔나

현재 진행한 것은 9개 상위 영역 중 **경로·차로 주행**과 **속도 유지**의 저속 직진 복구다. 같은 TRAIN 경로에서 개별 연구 기준을 만족한 실제 주행은 확보했지만, 3/3 재현성은 실패했다. 목표 경로 완주·종점 정차·30km/h·회전·새 지도·장애물 대응·실차 성능을 증명하지 않았다. 공식 하위 기능 승인 수는 **0/30**이다.

다음은 새 V2 모델의 실제 제어 연결이다. 별도 GPU 공동 학습 3,000회로 한 저속 TRAIN 구간의 경로 오차는 줄었지만 기존 DEV의 속도 손실이 악화됐다. 따라서 기존 여러 맵의 TRAIN 자료를 함께 재생하는 혼합 학습을 준비하고, 새 가중치도 지연·차체·정지·ACK를 실제로 검증한다. 새 헤드를 늘리는 것은 기본 주행을 확보한 다음이다.
