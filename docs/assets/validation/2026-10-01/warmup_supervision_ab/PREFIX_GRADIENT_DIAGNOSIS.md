# 멈춤을 고치는 학습 신호가 일부 구간에서 막히는가?

<!-- HH_261001 - Separate exact replay, derivative evidence, and an unproven live-causality hypothesis. -->

## 결론

**다음 학습 비교에서 검토할 구체적인 단서는 찾았다. 아직 원인 확정이나 해결은 아니다.**

W1 150초 주행에서 미리 1초 간격으로 저장한 입력 149개를 모두 사용했다. 기존 모델의 원래 출력을 **149/149 정확히 재현**한 뒤, 출력 값을 바꾸지 않고 미분만 계산했다. 1,483개 전체 추론을 모두 다시 확인한 것은 아니다.

| 질문 | 실제 결과 | 의미 |
| --- | --- | --- |
| 선택한 DRIVE의 앞쪽 2초 전체가 0이고 미분도 모두 막혔는가? | 0개 | ‘2초 전체가 학습 불가능’이라는 설명은 관측 결과와 맞지 않는다. |
| 제어기가 실제 사용하는 **0.3초 앞 속도**가 0이고, 그 값을 첫 3개 가속도 출력으로 바꾸는 직접 미분도 0인가? | 선택한 DRIVE 148개 중 **39개** | 당장 움직이는 데 필요한 속도 출력에 직접 회귀 학습이 전달되지 않는 상태가 있다. |
| 위 39개 중, 6.4초 전체 속도 합에서도 첫 3개 가속도 출력의 미분이 0인가? | **38개** | 먼 미래의 속도 오차를 함께 줄인다고 첫 동작이 자동으로 고쳐지는 것은 아니다. |

모델은 미래 속도를 한 단계씩 적분한 후 음수는 0으로 제한한다. 이 제한은 전진 속도 범위를 지키지만, 제한 바깥의 값에는 미분이 0이 될 수 있다. 그래서 ‘지금은 정지, 나중에는 가속’하는 예측이 남는 현상과 연결될 가능성이 있다.

그러나 입력을 처리하는 공통 네트워크와 다른 손실도 함께 학습하므로, 이것만으로 정지 원인을 전부 설명할 수 없다. 실제 주행 입력에는 다른 제어를 했을 경우의 정답 미래도 없다. 임의의 전진 후보를 정답으로 지정하거나 제어기에 강제 선택시키지 않았다.

## 이번에 바꾸지 않은 것

- W1 가중치, 궤적 출력, 속도·가속도 제한, 후보 선택, 차량 제어는 모두 그대로다.
- 학습 업데이트는 0회다. 실행 중인 W2 학습은 기존 조건 그대로 이어간다.
- 새로운 정답을 만들거나, 실패 자료를 TRAIN으로 편입하지 않았다.
- 최초 2초 가설의 [v1 결과](prefix_gradient_v1/result.json)와 당시 [실행 소스](prefix_gradient_v1/source/diagnose_w1_speed_prefix_gradient_20261001.py)를 보존했다. v1의 빈 집합에 대한 `all(...)=true` 값은 실제 사례가 있다는 뜻이 아니다. 후속 [v2 결과](prefix_gradient_v2/result.json)는 해당 항목을 `null`로 표현하고, 고정 제어기 시점인 0.3초를 추가 확인했다.

## 이어갈 비교

우선 같은 조건에서 학습량만 늘린 W2를 끝내고 평가한다. 별도로 **실행 시 속도 제한은 유지하면서 학습 때만 경계의 미분을 바꾸는 방식**이 타당한지 검토한다. 채택하더라도 새 사전계획과 동일 조건 대조군이 필요하며, 출력 동일성·정지 성능·직진·회전·차체 여유의 악화를 함께 검사한다. 현재 모델이나 실행 중인 학습에 바로 적용하지 않는다.

재현 명령:

```bash
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 CUDA_VISIBLE_DEVICES='' \
python3 -B tools/workspace_python.py -m unittest -- discover \
  -s learning/tests -p test_w1_speed_prefix_gradient_20261001.py -v
```

합성 경계 조건 3개 테스트 통과. 실제 입력 감사는 `diagnose_w1_speed_prefix_gradient_20261001`에서 **새 출력 경로**를 지정해 재실행할 수 있다. 기존 결과 파일은 덮어쓰지 않는다.
