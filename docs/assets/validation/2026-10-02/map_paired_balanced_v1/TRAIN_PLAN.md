# 지도 영상 조건을 함께 학습하는 비교 계획

새 Town01 p02·p04의 같은 틱 OFF/ON 자료에서 **영상 조건을 함께 학습하면 기존 조건을 잊지 않고 인식이 개선되는지** 비교한다. 주행 모델과 별개인 지도 인식 연구다. 정밀지도 완성·독립 장소 일반화·주행 기능 승인은 이번 학습의 결론이 아니다.

두 경로 모두 실제 240쌍 수집과 전수 QA를 마쳤다. 고정 0·119·239 프레임에서 OFF/ON 원본과 공통 7개 클래스 정답의 겹침을 확인한다. [검토 화면](../map_paired_appearance_review_v1/README.md)과 별도 검토 영수증을 필수 입력으로 사용한다. 원본의 `QA_CONDITIONAL`, `dataset_admitted=false`, `train_eligible=false`는 유지하고, 이 정확한 비교에만 파생 연구용 학습 권한을 기록한다.

## 자료와 유일한 비교 차이

기존 TRAIN 729장은 그대로 복습한다. 새 자료는 480개 물리 관측·960개 RGB 영상이다. 같은 관측의 OFF/ON은 독립적인 두 주행 장면이 아니며, 자료의 고유 영상 수는 1,689개지만 각 학습의 논리적 슬롯은 **729+480=1,209개**다.

| 비교 | 새 물리 관측의 영상 선택 | 나머지 조건 |
| --- | --- | --- |
| A 기준 | 언제나 OFF | 기존 729장·동일 물리 관측 순서·crop·정답·분류 가중치 유지 |
| B 혼합 | 미리 정한 OFF/ON 선택 | A와 같은 물리 관측·같은 횟수·같은 시작 가중치 |

B의 첫 방문은 각 경로에서 120개 OFF·120개 ON으로 고정하고, 이후 해당 쌍을 방문할 때마다 조건을 번갈아 사용한다. 모든 쌍의 OFF/ON 노출 횟수 차이는 최대 1이다. 실제 방문 수와 조건별 노출 수, 순서 SHA를 전부 기록한다. 두 경우의 자료 풀 크기를 다르게 해서 기존 729장 복습 비율까지 바꾸지 않는다.

목표 클래스는 기존 `other`, `road`, `sidewalk`, `lane_marking`, `traffic_light_fixture`, `traffic_sign`, `pole`이다. 공통 분류 가중치는 기존 729개와 새 물리 관측 480개의 정답을 **한 번씩만** 세어 계산한다. 깊이·semantic·정답 pose는 QA와 정답 생성에만 쓰며 RGB 모델 입력에 넣지 않는다. 가드레일 등 기존 7개 분류에 없는 세부 유형의 한계를 유지한다. p04에서 차선이 안 보이는 관측과 정차 구간도 제거하지 않는다.

## 학습과 평가

두 모델 모두 기존 B의 정확한 시작 가중치 `ff5d7d03a43b859d21a0a3f6b01d815054d89d78e850730121f326e5b79c023e`를 사용한다. 구조는 변경하지 않고 245,831개 parameter를 학습한다. 각 팔에 새 AdamW, learning rate `3e-5`, weight decay `1e-4`, gradient norm 상한 5, seed `20261002`, batch 8, 업데이트 **10,000회**를 사용한다. 각 팔의 실제 노출은 80,000회이며 같은 전체 epoch 순서와 같은 crop을 사용한다.

두 최종 10,000회 가중치를 모두 저장한 뒤에만 기존 known DEV 118장·이미 사용한 Town02 holdout 232장을 평가한다. 중간 가중치 중 좋은 것을 고르거나 평가 결과로 학습량을 변경하지 않는다. 모든 클래스의 IoU·정답/예측/오검출 픽셀과 원시 confusion을 남긴다. 기존 OFF/ON 외부 장면 평가는 추가 노출 진단으로 구분한다. TEST를 열거나 C-track을 학습에 넣지 않는다. 새 독립 DEV 장소는 **0개**다.

## 자원과 실패 경계

주행 공동 학습이 종료되고 GPU 0이 비어 있으며 개인 GPU lease를 획득한 뒤 직렬로 실행한다. 물리 GPU 0 UUID `GPU-59f374a4-53f5-c050-34b2-56aab0e3c7e5`와 개인 `hwanhong/portable_e2e/venvs/py312`만 사용한다. 설치·재부팅·다른 작업 종료·자동 배포는 하지 않는다.

source·자료·검토·계획 SHA와 원본 보관을 실행 전에 확인한다. 기존 출력은 덮어쓰지 않으며 5GiB+512MiB 쓰기 여유를 유지한다. 두 팔의 optimization 예산은 합계 1,800초다. 비정상 값·자료 변경·자원 충돌·예산 소진은 실패로 보존하고 자동 재시도나 resume을 하지 않는다. 모델 승격은 하지 않으며, 개선되지 않으면 기존 결과를 유지하고 조건별 오류와 다음 자료/학습 변경을 정한다.
