# 같은 주행 모델의 CPU 실행 지연 비교

**가중치를 다시 학습하지 않고 실행 시간을 줄일 여지는 확인했다. 실제 주행 개선 여부는 아직 별도 시험이다.**
Town07 중앙 출발 기록의 고정된 128개 시점을 CPU 1·2·4스레드에서 각각 계산했다.
세 조건의 정규화 입력 SHA는 전부 같았고, 같은 최종 6,000회 학습 가중치와 안전 검사를 사용했다.

| CPU 스레드 | 전체 호출 평균 | 전체 호출 p95 | 전체 호출 최대 | 이 오프라인 구간의 100ms 초과 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 80.61ms | 85.37ms | 91.82ms | 0/128 |
| 2 | 64.78ms | 67.76ms | 69.52ms | 0/128 |
| 4 | 55.46ms | 62.37ms | 64.96ms | 0/128 |

4스레드의 p95는 1스레드보다 약 27% 짧다. 입력 해시·전체 텐서 검사·추론·디코더·기존 PI 계산을 포함하며, 검사 생략이나 100ms 제한 변경은 하지 않았다.
JPEG에서 복원한 입력이므로 원래 CARLA 무손실 BGRA와 픽셀까지 같다고 주장하지 않는다.
또한 실시간 카메라 노출부터 명령 ACK까지의 지연, 전체 10Hz, 실제 차량의 동작을 측정한 시험이 아니다.

## 출력이 완전히 같았나요?

**사전에 정한 전체 출력 `1e-6` 비교는 실패했다. 이 결과를 통과로 고치지 않는다.**
원 신경망 출력은 모든 조건·128개 시점에서 그 오차 범위 안이었다. 하지만 디코더가 위치 차이를 0.1초로 나눠 속도로 바꾸면서 작은 float32 차이가 커졌다.

- 2스레드: 위치 차이 최대 약 0.00000346m, 구간 속도 차이 약 0.00001932m/s. 제안 제어값 비교는 1/128 불일치.
- 4스레드: 위치 차이 최대 약 0.00000313m, 구간 속도 차이 약 0.00001908m/s. 제안 스로틀·브레이크·조향의 `1e-6` 비교는 128/128 일치.
- 관측된 GO/STOP, 후보 선택, 안전 검사, 제어 포화·부호 분기는 세 조건 모두 같았다. 이후 모든 장면에서 같을 것이라는 보장은 아니다.

이 근거로 **별도 선언한 4스레드 연구 설정**을 실제 CARLA의 같은 세 출발 조건에서 비교한다.
기존 선언·실패·엄격한 비교 결과를 보존하며, 새 설정을 “완전 동일 출력”이나 승인된 배포 모델로 부르지 않는다.
주행거리 90m·실제 속도 상한 2.5m/s·제어 100ms·차선/차체 여유 기준은 그대로 유지한다.
CPU 시간을 줄여도 이전 89.36m/88.71m 거리 미달까지 자동 해결되는 것은 아니다.
