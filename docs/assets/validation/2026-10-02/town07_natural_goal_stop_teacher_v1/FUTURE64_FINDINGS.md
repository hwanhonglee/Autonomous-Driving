# 목적지 정지 v1: 실제 미래 궤적 검사 결과

결론: 차량은 목적지 근처에서 멈췄지만, 급감속 때문에 이 자료는 학습에 사용할 수 없습니다. 실패한 원본과 모든 검사 구간은 그대로 보존했습니다. 이것은 **교사 주행 수집 시험**이며, 학습 모델의 정지 성공이 아닙니다.

근거는 [실제 검사 요약](../../../../../storage/experiments/validation/2026-10-02/town07_natural_goal_future64_audit_v1/summary.json)과 [929개 구간의 전체 미래 검사](../../../../../storage/experiments/validation/2026-10-02/town07_natural_goal_future64_audit_v1/all_fixed_anchor_true_future64.jsonl)입니다. [검사 코드](../../../../../tools/e2e/audit_town07_natural_goal_future64_20261002.py)는 실제 속도·위치·시각을 바꾸지 않았습니다.

## 무엇을 검사했나

20Hz 상태 2,092개와 10Hz 카메라 묶음 1,046개, 실제 6카메라 이미지 6,276장을 보존했습니다. 미리 정한 규칙에 따라 주행 시작 4초 이후부터 실제 2초 정지 유지가 끝날 때까지의 앵커 929개를 검사했습니다. 각 앵커의 **실제 미래 6.4초, 64개 위치·차량 방향·속도**를 모두 복원했으며, 총 59,456개 미래 점 중 잘라낸 점은 없습니다. 후반 정지 기록은 미래 정답을 만드는 문맥으로만 사용하고 학습 앵커로 추가하지 않았습니다.

같은 프레임의 실제 교사 기록에 연결된 현재 의도는 GO 897개, BRAKE_TO_STOP 12개, HOLD 20개입니다. 이들은 정답 라벨이며 모델 입력으로 제공할 정보가 아닙니다. 겹치는 앵커 929개는 독립된 주행 929회가 아니라 **한 번의 교사 주행**에서 나온 구간입니다.

## 왜 실패했나

주행 상대 시각 약 94.8초에 실제 속도가 다음처럼 급격히 줄었습니다. 감속 수치는 20Hz 원본 속도의 시간 차분이며, 별도로 기록된 API 가속도 벡터 크기와 혼동하지 않습니다.

| 실제 프레임 구간 | 속도 변화 | 실제 시간 차분 가속도 |
| --- | --- | --- |
| 3675 → 3676 | 1.53710 → 0.72129 m/s | −16.31612 m/s² |
| 3676 → 3677 | 0.72129 → 0.000851 m/s | −14.40887 m/s² |

두 구간 모두 기존 물리 한계 ±2.9 m/s²와 별도 원본 상태 검사 ±3.0 m/s²를 넘었습니다. 해당 원본 구간을 과거 또는 미래로 포함하는 **앵커 75개가 실패**했습니다. 실패 구간만 빼서 나머지를 좋은 학습 자료로 만드는 작업은 하지 않았습니다. 충돌·차선 침범 이벤트가 0개라는 사실도 이 급감속 실패를 상쇄하지 않습니다.

원본 수집 상태와 owner 검사는 실패로 남아 있습니다. 이 미래 전용 감사는 body 검사를 다시 수행하지 않았고, 이전 body 증거가 없거나 통과하지 못한 경우를 NOT_PROVEN으로 유지합니다. 따라서 전체 차량 차체 안전이나 학습 적합성을 승인한 결과가 아닙니다.

## 정지 곡률을 0으로 바꾼 것인가

아닙니다. 정지 상태에서는 이동 방향을 거리로 나누는 곡률이 정의되지 않거나 수치적으로 불안정합니다. 해당 항목은 `null`과 유효 마스크 `false`로 남겨 **평가·학습 정답이 없는 항목**으로 구분했습니다. “곡률 0 정답”이나 “검사 PASS”로 바꾸지 않았습니다.

실제 미래 위치·속도·차량 방향은 그대로 유지했고, 기존 곡률 공식의 위반 기록도 별도로 보존했습니다. 속도·감속 검사는 마스킹하지 않았습니다. 따라서 정지 곡률의 정의 문제를 구분해도 앞의 급감속 실패와 앵커 75개의 실패는 그대로입니다.

## 디코더 설계에서도 확인된 문제

현재 교사가 아직 GO로 주행하는 앵커 중 **65개는 실제 남은 경로가 18m 미만**이었습니다. 기존 주행 디코더는 GO에 18m 이상의 경로 지원을 요구하므로, 현재 구조를 그대로 사용하면 정상적인 목적지 접근 구간까지 거절하게 됩니다. 이 65개는 앞의 급감속 실패 75개와 다른 검사 항목이며, 숫자만으로 같은 구간이라고 볼 수는 없습니다.

또한 기존 BRAKE_TO_STOP 디코더는 일정 감속만 표현합니다. 기존 speed/a0 출력 헤드는 이 제동 궤적을 결정하지 않습니다. 정지 헤드를 켜거나 학습 횟수만 늘리는 것으로 실제 감속 과정을 재현할 수 있다고 단정할 수 없습니다.

다음 단계는 급감속 없는 **새로 선언한 교사 수집 조건**을 먼저 검증하는 것입니다. 이후 실제 정답을 넣었을 때 디코더가 전체 접근·제동·정지를 얼마나 재현하는지 확인하고, 필요하면 실제 경로 끝과 예측한 정지 거리를 함께 사용하는 별도 디코더 버전을 설계합니다. GO를 억지로 BRAKE로 바꾸거나 경로를 연장해 통과시키지 않으며, 기존 rolling 주행 모델과 회귀 검증은 보존합니다.

현재 결과는 학습·실차·기능 승인 자료가 아닙니다. 공식 메인 기능 **0/9**, 서브 기능 **0/30** 상태를 유지합니다.
