# 목적지 정지 교사 v2 — 도착했지만 급감속으로 실패

<!-- HH_261002 - Preserve all actual failed intervals and distinguish teacher completion from model/data approval. -->

결론부터 말하면, **이 자료도 학습에 넣으면 안 됩니다.** 차량은 목적지 상류 0.974 m에서 실제로 2초간 정지했고, 차체·ACK·카메라·소스 확인도 통과했습니다. 하지만 주행 중 급정지를 반복하여 실제 감속 품질이 실패했습니다. “도착 성공”과 “부드럽고 학습 가능한 주행”은 서로 다른 결과입니다.

이번 실행은 학습 모델의 정지 시험이 아니라 **BasicAgent 교사 데이터 수집 시험**입니다. 주행 모델의 학습된 정지 기능이나 실차 정지를 승인한 결과가 아닙니다.

## 무엇을 바꾸고, 무엇을 유지했나

같은 Town07 경로·seed·날씨·차량·manual 1단·20 Hz 물리·10 Hz 6카메라를 사용했습니다. 실행 전에 두 값만 함께 변경했습니다. 따라서 두 변경 중 어느 하나의 인과 효과를 따로 입증한 A/B 시험은 아닙니다.

## 급정지 순간에는 무엇이 실제로 적용됐나

10개 위반 모두 직전 프레임에서 받은 ACK 요청, 다음 native 상태의 `current_control`, 직전 상태의 `next_control`이 서로 연결됩니다. 공통 제어는 **throttle 0, brake 0.009999999776482582, manual_gear_shift true, gear 1**입니다. 이는 0.01 요청의 실제 float32 표현이며 값을 잘라서 만든 기록이 아닙니다.

다음 표는 전체 10개 위반을 모두 남깁니다. 속도는 m/s, 감속은 m/s²입니다. 시각은 첫 driving 상태부터 실제 timestamp 차이입니다. rear-base 속도와 CARLA actor의 실제 world velocity 평면 노름을 따로 표시했습니다.

ACK의 `before_frame`은 각 행 왼쪽 프레임이며, 모두 `ACKNOWLEDGED`였습니다. 정상 제동 페달은 0.01을 넘지 않았고, 이 10개 구간에서 full brake 1.0을 미리 보낸 흔적은 없습니다. 첫 stationary-tail full brake는 **frame 4287**로, 마지막 위반 frame 4246과 driving HOLD 완료 frame 4286보다 뒤입니다. 조기 tail 전환으로 이 급감속이 생겼다는 설명은 맞지 않습니다.

특히 frame 4081→4082에서는 실제 속도가 50 ms 만에 거의 0이 됐지만 목표 속도는 1.029947→1.025942 m/s로 아직 양수였습니다. 다음 frame 4083부터 throttle 0.20으로 다시 가속했습니다. 이와 유사한 **가속→0.01 제동→거의 정지→재가속** 패턴이 반복됩니다.

카메라가 끊겨서만 그렇게 보이는 것은 아닙니다. actor의 world velocity와 API 가속도에도 같은 급감속이 기록되어 있습니다. 다만 rear-base scalar `dv/dt`와 API 가속도 벡터 노름은 서로 다른 정의이며 완전히 같은 숫자라고 주장하지 않습니다. ACK 성공도 물리 페달 반응의 원인 전체를 증명하지는 않습니다. 현재 증거만으로 CARLA 차량의 제동/구동 내부 원인을 확정할 수는 없습니다.

## 미래 64개 감사 결과

전향적으로 정한 `t_driving ≥ 4 s`부터 실제 2초 HOLD 완료까지 **1,022개 창을 전부** 검사했습니다. 각 창의 실제 미래 64개, 합계 **65,408개 XY·yaw·순간 속도 라벨**을 보존했습니다. raw startup도 보존했고, 130개 tail 상태는 미래 문맥으로만 사용했습니다. 실패한 창을 삭제하거나 좋은 창만 고르지 않았습니다.

- 실패 창 181개가 모두 protected native 구간에 위 10개 급감속 중 하나 이상을 포함합니다. 보호 범위 밖 위반은 0개입니다.
- 100 ms 미래 라벨의 정의된 운동/곡률 기준까지 실패한 창은 170개입니다. 181개와 중복되므로 더해서 세지 않습니다.
- 현재 교사 의미 라벨은 GO 844개, BRAKE_TO_STOP 157개, HOLD 21개입니다.
- GO 12개는 남은 실제 경로 길이가 기존 decoder의 18 m 조건보다 짧습니다. GO를 BRAKE로 바꾸거나 경로를 외삽하지 않았습니다.
- 정지 상태의 곡률은 수학적으로 정의되지 않으면 `null`과 invalid mask로 남깁니다. 0이라는 정답으로 바꾸거나 급감속을 mask로 숨기지 않습니다.

native 자료의 PENDING_QA 상태에는 명시적 Boolean 학습 거부 필드가 없지만, **그 사실이 학습 허가가 아닙니다.** 원래 denial guard를 실행했고 raw 거부를 무시하지 않았습니다. 연구 학습·holdout 평가·차량 제어 승인은 모두 false입니다. 모든 선언된 live/archive 소스 86개·외부 파일 11개·asset 5개와 모든 JPEG 바이트를 대조했습니다. 기존 차체 감사는 PASS였지만 전체 교사 capture/품질은 FAIL로 유지했습니다.

## 다음에 해야 할 일

이번에는 0.01보다 작은 페달 값을 또 추측하여 반복하지 않습니다. 먼저 같은 차량·기어·물리 설정을 고정한 **별도 제동/구동 응답 계측**으로, PID/목표 속도 피드백 없이 실제 pedal→속도 변화와 저속 제동 직후 재출발을 확인해야 합니다. 그런 뒤 원인에 맞게 교사 제어를 고치고 새 자료를 전향적으로 수집합니다. 현재 v1/v2 실패 자료는 지우거나 학습용으로 승격하지 않습니다.

부드러운 실제 정지 자료가 확보되더라도, 기존 decoder의 짧은 GO 경로와 BRAKE 일정 감속 식이 실제 미래를 표현할 수 있는지 먼저 확인해야 합니다. 모델의 의미 head 학습은 그 다음입니다. 주행 모델의 rolling 성능 회귀 검사도 함께 유지합니다. **정식 MAIN 승인 0/9, 하위 승인 0/30**입니다.
