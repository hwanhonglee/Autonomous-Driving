# 원래 209m 직진 경로 — 목표 도달, 처리 지연은 아직 미달

이번 로컬 CARLA 시험에서는 **원래 목표점에 실제로 도달했다.** 출발 초기에만 교사가 제어했고, 그 뒤에는 기존 GOOD6000 모델의 곡률·속도 출력을 사용했다. 종점 근처의 짧은 경로는 실제 위치와 전체 경로를 인증하는 별도 내비게이션 제약기로 처리했다. 모델이 정지를 학습했다는 뜻은 아니다.

**종합 판정은 FAIL이다.** 원래 100ms 기준을 한 번 초과했고, 새 종점 기록을 기존 검사기가 처리하지 못했다. 기존 결과를 PASS로 덮어쓰지 않는다. 정식 승인 수는 **메인 0/9·세부 0/30**이다.

## 왜 아직 실패인가

주행 행동과 검사기 문제를 나눴다.

1. **실제 처리 지연:** 일반 주행817회는 모두100ms 이내였다. 종점 처리66회 중 frame5685 한 번이113.31ms였다. 그때 NN 이후 종점 계산 구간이35.54ms로 길었다. 내부 계산·메모리 정리·스케줄링 중 어느 원인인지는 추가 계측 전 단정하지 않는다.
2. **기록 이름 처리:** 실제 새 종점 ACK `catalog_goal_terminal_cleanup`을 기존 검사기가 모른다. 이 오류가 이후 경로·녹화 요약 계산도 중단시켰다. 실제 영상이 없는 것은 아니다.
3. **기어 검사:** 기존 제동 생산자의 실제 설정은 `gear=1`, `manual_gear_shift=True`인데 새 검사기는 `0/False`를 요구했다. 액추에이터를 바꾸는 대신 원래 설정을 검증하도록 새 검사기를 만든다.
4. **거리 비교:** 종점 출력66개 모두 인증된 witness의 실제 D·경로·잔여 거리와 정확히 일치했다. 한 프레임에서 두 기존 경로 투영식 사이의 약 `2.84×10⁻¹⁴m` 차이를 검사기가 잘못 실패 처리했다. 허용 오차를 늘리지 않고 독립 재계산한 witness를 정확한 비교 대상으로 쓴다.
