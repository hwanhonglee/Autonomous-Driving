## 이번 확인의 범위

CPU 환경의[실제 검사 기록](../../../../storage/experiments/diagnostics/2026-10-07/nontraining_cpu_ros_environment_v1/result.json)은 일반 셸에 섞여 있던 다른 Autoware 설치 경로를 상속하지 않고 현재 작업공간의 생성 메시지를 사용했습니다. ## 지도 첫 실행에서 찾은 문제

<!-- HH_261007 - Preserve the actual failed480 denominator and explain the genuine-pose inverse bug without changing thresholds or model weights. -->

[V1 실제 결과](../../../../storage/experiments/diagnostics/2026-10-07/mapping_no_training_v1/result.json)는 첫 프레임에서 종료됐습니다. 원래 영상·예측·소스는 검사 전후 동일하며 완료0·실패1·미실행479입니다. 합격한480프레임으로 표기하지 않습니다.

원인을 실제 저장된 첫 카메라 위치로 확인했습니다. 검증기가 회전 행렬의 전치만으로 역변환하면서 저장 정밀도 오차를 무시했습니다. 이 방법의 픽셀 복원 오차는0.00003149로 기존 기준0.000001을 넘었습니다. 같은 위치를 실제 행렬 역변환으로 계산하면 오차는약0.00000000000182입니다. 영상 인식이나 모델 가중치를 고쳐서 얻은 차이가 아닙니다.

V2는 이 계산을 수정하고 실제 정밀도의 회전 행렬을 회귀시험에 추가했습니다. 새 검사 29개가 통과한 뒤 [실제 전량 결과](../../../../storage/experiments/diagnostics/2026-10-07/mapping_no_training_v2/result.json)에서 **480/480프레임, 누적 상태 1,440개, 최종 격자 6개**가 원래 저장 상태와 일치했습니다. 실제 소요 시간은 399.60초, 실패·미실행은 0개입니다. 최대 좌표 차이는 0m, 최대 픽셀 역변환 오차는 약2.39×10⁻¹²로 기존 기준 안입니다. 원본·가중치·검사 기준은 바꾸지 않았습니다.

이는 저장된 예측의 좌표와 누적 검증이지, 최신 지도 모델의 인식 성능·실제 위치 정확도·정밀지도 완성의 증거는 아닙니다. PNG를 새로 만들거나 픽셀을 다시 검사한 결과도 아닙니다. [기존 실제 지도 그림과 인식 오류](../2026-10-01/map_geometry_full_projection/README.md)를 별도로 보존합니다. CTrack 원래 실패·학습 금지·정답 깊이와 위치 사용의 한계도 유지합니다.

[별도 후검산](../../../../storage/experiments/diagnostics/2026-10-07/mapping_no_training_v2_independent_postcheck_v1.json)은 전체 480개 순서·1,440개 좌표와 관측 범위 기록·2,482개 입력 파일 해시 및 V1 실패 보존을 확인했습니다. 최종 격자를 별도 수치 실행으로 한 번 더 재생한 것은 아닙니다. 기존 geometry 모델의 차선 셀 IoU는 좌회전 9.34%·직진 21.88%로 낮고 도로 주변 오검출도 남아 있습니다. 따라서 다음 인식 학습 과제는 해결됐다고 말하지 않습니다.

V4의 75개 준비 검사는 통과했고, [실제 직접 추론](../../../../storage/experiments/diagnostics/2026-10-07/temporal_recorded_ros_shadow_v4/direct_result.json)은 **전체 918개 입력을 처리 완료**했습니다. 이어서 같은 입력을 ROS로 보내는 단계는 수신 0/918개로 실패했습니다. 설치된 ROS Executor가 콜백에 메시지 한 개만 전달하는데 실행기가 메시지와 발신자 정보 두 개를 요구한 API 호환성 문제입니다. 가중치나 차량 제어 문제로 단정하지 않습니다. 전체 실패와 미실행 꼬리를 남기며, 직접 추론 완료를 DDS 동등성·10Hz·Autoware 차량 주행 성공으로 세지 않습니다.

[V4 독립 전량 검산](../../../../storage/experiments/diagnostics/2026-10-07/temporal_recorded_ros_shadow_v4_independent_postcheck_v1.json)에서 실제 NN 계산 918회, 궤적 출력 838개·과거 문맥 준비 54개·안전 거절 26개를 확인했습니다. 거절 이유는 관측된 역방향 이동 4개, 주행 가능한 앞쪽 예측 거리와 제동 여유 부족 22개입니다. 이를 삭제하거나 정상 궤적으로 바꾸지 않습니다. 원래 모델 판단 시간은 평균 54.61ms·최대 99.01ms지만, 검사 기록까지 포함하면 평균 88.12ms·최대 138.54ms이고 28개가 100ms를 넘었습니다. 이는 DDS 지연·전체 주행 10Hz와 다른 측정입니다. 입력 5,524개·현재/보존 소스 54개·생성 ROS 소스 42개 해시는 모두 일치하고 해당 실행 프로세스는 종료됐습니다.

[모델 없는 실제 메시지 검사](../../../../storage/experiments/diagnostics/2026-10-07/native_dds_info_probe_v1/result.json)에서도 설치된 native API가 시간 정보 두 개만 반환하고 발신자 GID는 제공하지 않는 것을 확인했습니다. 그래프에서 가져온 GID를 실제 메시지 GID처럼 만들어 넣지 않습니다. 시스템 패키지 설치·업데이트 없이, 기존 공개 C API로 실제 수신 메시지의 정보를 보존할 수 있는 프로젝트 전용 호환 방식을 검토합니다. 호환 수정의 성공 여부는 별도 실제 검사로 판단합니다.

설치된 헤더와 [ROS 원본 구현](https://github.com/ros2/rclpy/blob/humble/rclpy/src/rclpy/subscription.cpp)을 함께 확인했습니다. 공개 subscription 포인터가 가리키는 `rcl_subscription_t`와 `rcl_take`의 실제 메시지 정보를 사용하며, 메시지 생성·변환·해제는 기존 생성 메시지의 함수를 사용합니다. 이 호환 코드는 주행 모델·센서 보정·안전 기준을 바꾸는 작업이 아닙니다. 새 코드·비공개 실험 출력·현재 ABI를 별도로 고정하고, 작은 송수신 검사를 통과하기 전 전체 재실행하지 않습니다.
