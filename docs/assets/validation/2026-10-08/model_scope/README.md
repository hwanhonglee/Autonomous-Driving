## 주행 모델은 무엇을 보고 무엇을 내보내나요

현재 기록 입력 비교가 사용하는 것은 10월2일의 GOOD6000 연구 가중치입니다. 이름의 GOOD는 이 프로젝트 안의 비교 기준일 뿐, 안전 인증이나 실차 사용 승인을 뜻하지 않습니다. [실제 가중치 설명](../../../../../storage/experiments/training/2026-10-02/temporal_route_joint_v1/exports/step_006000/metadata.json)의 SHA는 `a4b2c35cbc782378a5464ba8daa69ff97cea3ac388567ba260d4f2934381be04`입니다. 9월의 v0·physical-v1 설명과 현재 구조를 혼동하면 안 됩니다.

```text
6개 카메라 × 현재와 과거 5시점
  → 공유 CNN → 각 이미지의 6×10 격자 특징
카메라 보정 + 과거 차량 상태 10개 + 목적지 방향 경로 최대128점
  → 같은 특징 공간으로 변환
  → 32개 질의가 필요한 특징을 모으는 fusion block 2개
     (각 block의 cross-attention과 query self-attention)
  → 곡률·희망 속도 등의 원시 출력
가까운 경로 2m·4m·8m의 횡방향 위치/접선/유효 여부
  → 학습된 작은 보정 분기 → 곡률 출력에 보정
  → 별도 경로 해석·물리 제한·유효성 검사
  → 궤적/속도 제안 → 별도 차량 제어기
```

이미지는180×320 RGB이고 과거 시점은 현재 기준 −0.8·−0.6·−0.4·−0.2·0초입니다. 없는 과거를 현재 이미지 복제로 채우지 않습니다. 캐시 실행은 이미 인코딩한 과거 이미지를 재사용하지만, 입력·가중치·시간 연결 검사는 유지합니다.

여기의 보정값은 **카메라 위치와 화각을 알려주는 입력**입니다. 그 값을 넣었다고 자동으로 정확한 3D BEV나 정밀지도가 생기는 것은 아닙니다. 가까운 경로 분기도 현재 제공된 내비게이션 경로만 사용합니다. 실제 미래 차량 위치를 정답처럼 런타임에 넣거나, 교사 궤적을 모델 출력으로 바꾸지 않습니다.

코드는 [기본 시공간 모델](../../../../../learning/portable_e2e/temporal_model_v2.py), [학습된 가까운 경로 보정 분기](../../../../../learning/portable_e2e/temporal_route_recovery_v3_20261001.py), [현재 가중치 로더](../../../../../learning/portable_e2e/temporal_route_joint_export_research_20261002.py)입니다. 모델은 throttle·brake·steering을 직접 내보내는 구조가 아닙니다. 실제 구동의 성공은 뒤쪽 제어기와 폐루프까지 확인해야 합니다.

## 6,000회 학습이 무엇을 바꿨나요

실제 설명 파일에는 TRAIN18개 episode·HOLDOUT2개 episode, 추가 optimizer 갱신6,000회·표본 노출24,000회가 기록돼 있습니다. **24,000개 독립 장면을 새로 수집했다는 뜻은 아닙니다.** 같은 자료의 반복 노출을 포함합니다. 학습 횟수가 충분한지는 횟수 자체가 아니라 독립 평가와 폐루프 결과로 판단합니다.

| 구성 | 최근6,000회 학습에서의 상태 | 해석 |
| --- | --- | --- |
| 영상 CNN·입력 embedding | 동결 | 이 단계에서 새로운 인식 능력을 학습한 것이 아님. 이전 학습 이력과 구분 |
| attention 결합부·trunk·곡률·속도·경로 보정 분기 | 갱신 | 총54개 상태 tensor, 학습 parameter2,277,827개. 54개 기능이나54개 layer라는 뜻이 아님 |
| 의도·정지 거리·가속도 head 및 기타 입력 상태 | 동결 상태에 포함 | 남은47개 상태에는 상수 buffer도 포함. 구조상 존재와 기능 학습을 구분 |

head의 가중치를 동결해도 앞쪽의 공유 trunk가 바뀌면 그 head의 출력은 달라질 수 있습니다. 현재 설명 파일도 `semantic_outputs_preserved=false`입니다. 따라서 기존 출력 보존은 동결 여부만으로 주장하지 않고 별도 회귀 시험으로 확인해야 합니다.

현재 export는 `stop_intent_trained=false`이고, 런타임 의도는 **head에서 선택한 판단이 아니라 명시된 cruise GO**입니다. 정지 head가 있다는 이유로 신호 정지·목표 정지·AEB가 학습됐다고 말할 수 없습니다. 종점 안전 정지 로직이 개입했다면 학습된 정지 행동과 별도로 검증해야 합니다.

10월5일의 세 추가 학습과 평가도 이미 종료됐습니다. 새 세 모델은 HOLDOUT 경로 오차가 기존 기준보다 커져 채택하지 않았습니다. 지금 학습 중인 작업은 없습니다. [완료 학습·미채택 근거](../../2026-10-05/README.md)를 유지합니다.

## 지금 비학습 개선과 모델 성능 개선의 차이

메모리 배치와 CNN 컴파일은 **같은 답을 더 빨리 계산하려는 실행 변경**입니다. 차선·신호·장애물을 새로 배우게 하는 작업이 아닙니다. 100ms 관문을 지키고 전체 원시 출력 동등성·실패 꼬리를 검산한 뒤에만 속도 개선을 판단합니다. 현재 실제 비교는 기준 미달이며 [실행 지연 결과](../driving_ros/README.md)에 정리합니다.

앞으로 주행 능력을 개선하려면 첫째로 독립 직진·회전·종점 정지 시험을 같은 조건에서 확보해야 합니다. 행동이 틀린 경우에는 원래 실패를 평가 근거로 보존하고, 별도로 허용된 TRAIN 수집에서 교사의 **관측된 진짜 미래·복구 과정·감속/정지**를 학습 정답으로 만들어야 합니다. 지연 실패를 단순히 optimizer 횟수 증가로 해결하거나, 정지 정답 없이 head만 추가하지 않습니다.

기본 주행을 안정화한 뒤 신호 준수·ACC·회피·차선변경을 추가합니다. 기능마다 필요한 장면, 정답, 손실과 독립 폐루프 시험이 다릅니다. 새 기능 학습은 기존 직진·회전 자료의 replay와 회귀 평가를 함께 써서 기존 기능이 망가졌는지도 확인해야 합니다. 이번9시까지 작업에서는 학습을 실행하지 않습니다.

## 지도 모델은 어디까지 구현됐나요

현재 지도 인식은 작은 RGB semantic 모델입니다. [기본 모델](../../../../../learning/portable_e2e/map_perception.py)에 가까운 특징을 유지하는 skip 연결이 있고, [문맥 확장 후보](../../../../../learning/portable_e2e/map_context_recovery.py)는 더 넓은 주변 특징을 보는 residual 분기를 추가합니다. 출력은 도로·보도·차선 표식·신호등 구조물·표지판·기둥과 미확인 `other`의7종입니다. 신호등 구조물을 인식하는 것과 빨강/노랑/초록을 판단하는 것은 다릅니다.

인식 결과를 세계 좌표로 옮기려면 [별도 투영 코드](../../../../../learning/portable_e2e/mapping_projection.py)에 **깊이·카메라 보정·위치·시각·출처**가 추가로 필요합니다. 가상환경의 정답 깊이와 실제 센서/추정 깊이는 다릅니다. 투영·누적이 맞아도 차로 연결, 정지선과 신호등의 관계, Lanelet2 정밀지도 품질이 자동으로 입증되지는 않습니다.

현재 후보는 오탐을 줄이는 대신 일부 정답을 더 놓쳤습니다. 다음 학습 설계에서는 표지판이 증강 crop에서 보존되는지와 누락·오탐의 균형을 함께 다뤄야 합니다. [실제350장 분석과 정답 노출 검산](../mapping_review/README.md)을 근거로 쓰되, 노출된 Town02 진단 자료를 새 독립 TEST라고 부르지 않습니다.

주행 모델은 자동 생성 HD map을 필수 입력으로 요구하지 않습니다. 자동 지도 보조 입력은 나중에 별도의 있는/없는 비교로 검증할 대상입니다. 현재 지도 모델의 결과를 현재 주행 성공의 근거로 합치지 않습니다.
