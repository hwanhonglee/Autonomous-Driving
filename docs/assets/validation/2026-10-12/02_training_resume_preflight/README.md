NVML은 GPU 상태 조회에 쓰이는 라이브러리입니다. 현재 메모리에 로드된 드라이버와 디스크의 라이브러리가 다릅니다. NVIDIA도 이 종류의 오류를 드라이버·라이브러리 버전 불일치로 정의합니다. [NVIDIA NVML 오류 정의](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceEnums.html).

이는 **서버 인프라 문제**이며 모델 행동·학습 데이터·인식 성능을 시험하다 실패한 것이 아닙니다. 깨끗한 환경에서도 오류를 확인했으므로 단순 PATH 변경으로 정상화됐다고 볼 수 없습니다. GPU 0의 현재 UUID·빈 메모리·다른 작업 유무는 확인하지 못했으며 GPU가 놀고 있다고 가정하지 않습니다. Torch도 import하거나 CUDA를 초기화하지 않았습니다.

## 지금 필요한 서버 조치

공유 서버 관리자에게 **로드된 NVIDIA 모듈과 설치된 라이브러리의 버전을 일치시키고 GPU 조회를 복구해 달라**고 요청해야 합니다. 관리자에게 전달할 핵심은 `580.173.02 / 580.178.04`, `nvidia-smi -i 0` 실패와 종료값 18입니다. 어떤 조치가 가능한지는 다른 사용자의 작업과 서버 운영 조건을 확인한 뒤 결정해야 합니다.

이번에는 재부팅·모듈 재로딩·드라이버 재설치·라이브러리 우회·다른 사용자 프로세스 종료를 하지 않았습니다. 개인 venv에 패키지를 추가하지 않았고 서버 파일도 변경하지 않았습니다. 서버 관리 조치와 모델 학습은 다른 권한 범위입니다.

## 서버가 정상화돼도 남아 있는 구현

현재 지도 crop-only trainer는 아직 구현 전입니다. 이전에 완료한 구조 A/B 학습의 실행기·권한을 재사용하지 않습니다. 새 비교는 같은 모델·초기 수치 상태·손실·optimizer·순서를 사용하고 crop만 바꿉니다.

추가 소스 검토에서 전체 20,000배치로 확대할 때 두 가지 문제가 확인됐습니다. 기존 입력 어댑터는 입력 행과 ACK 목록을 누적하므로 **16배치의 약 369MiB 관측만으로 전체 학습 메모리를 보장할 수 없습니다.** 또한 어댑터 종료가 reader를 닫으므로 작은 묶음 사이의 실제 FD·캐시 소유권도 새로 구현해야 합니다. 서버 배포는 라이브러리의 package 상대 import를 보존해야 하며 기존 flat worktree 실행기를 그대로 쓸 수 없습니다.

8배치 단위 묶음의 기존 파일 한도를 적용하면 두 군의 입력 기록 한도만 **937.5MiB**입니다. 이는 소스 기반 용량 계획이며 실제 전체 실행 결과가 아닙니다. 업데이트·ACK 기록·파일시스템 부가 공간·모델 저장·종료 여유는 별도로 필요합니다. 기존 FIRST16의 2MiB 권한을 전체 학습에 확대하지 않습니다.
