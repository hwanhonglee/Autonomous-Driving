## 전체 목표에서 지금 어디에 있나요

주행 모델은 센서·상태 이해, 경로·차로 주행, 속도·승차감, 교통규칙·교차로, ACC, 장애물 대응, 차선변경·합류, 저속 정차·주차, 런타임 안전·실차 전환의 **9개 영역·30개 하위 기능**을 목표로 합니다. 기본 직진·좌우회전·속도 추종·종점 정지를 안정화한 뒤 추가 기능으로 진행합니다.

자동 지도 모델은 별도입니다. 현재 7종의 도로·정적 요소 인식과 좌표 투영·누적을 다룹니다. 실시간 센서와 주행 기록 두 입력을 지원하는 것이 목표지만, 현재 구현만으로 정밀지도·Lanelet2 품질이 승인되지는 않습니다. 주행은 자동 생성 HD map 없이도 가능하도록 만들고 지도 보조는 별도 비교합니다.

## 이번에 실제로 바뀐 부분

앞선 NumPy 입력 어댑터 뒤에 CPU Tensor 복사·검사기를 구현했습니다. 두 군 모두 같은 128회 입력을 사용했고, 실제 표지 정답 복구 **2회**가 Tensor와 수신 확인까지 유지됐습니다. 256개의 독립 장면이나 모델이 표지판을 2개 더 인식한 결과는 아닙니다.

관측 최대 메모리는 약 **369MiB**, 종료 seal **62개 일치**, 미확인 입력·종료 정리 오류는 0입니다. 입력 변환기 합성 시험 **48개**, 실행기 스칼라·가상 파일 시험 **35개**와 독립 검사기 시험 **47개**가 통과했습니다. 별도 코드의 **지정 파일 69개·전체 선언 기록 저장 검산도 9.78초에 완료**했습니다. 배열을 다시 계산한 검산은 아니며 실제 비교·저장 검산·모델 성능 평가를 구분합니다.

새 설치·원본 삭제·기존 가중치 변경·실험 덮어쓰기·레거시 링크 복원·commit·push는 하지 않았습니다. 기존 실패 분모와 합격 기준을 유지했습니다.

## 다음 진행 순서

1. **학습 없이 새 trainer 연결 구현:** 검증한 단일 프로세스 어댑터를 새 trainer 소스에 연결합니다. 전체 20,000배치의 출력 묶음·메모리·용량·시간·종료점·실패 기록 조건을 따로 선언합니다. 현재 FIRST16의 권한과 2MiB 용량을 전체 학습에 재사용하지 않습니다.
2. **같은 모델에서 crop만 바꾸는 지도 학습 준비:** 두 군 모두 같은 MapContextRecovery·시작 수치 상태·weighted CE·fresh AdamW·seed·입력 순서를 사용합니다. 기존 구조 비교를 재사용하거나 새 head·loss를 함께 넣지 않습니다. 초기 가중치·RNG·parameter 순서·빈 optimizer·서버 provider를 확인해야 실제 비교가 됩니다.
3. **PRO6000 학습·독립 평가:** 접속·개인 venv·물리 GPU 0·허용 TRAIN과 평가 범위·NN/역전파 사전 검사·고정 종료점을 확인한 뒤에만 실행합니다. 기존 DEV를 새 TEST로 부르거나 미승인 raw를 TRAIN에 넣지 않습니다. 학습 후 표지 누락·오탐·다른 분류 회귀를 비교합니다.
4. **주행은 첫 기능부터 별도 검증:** 같은 모델의 출력 동등성·100ms 지연→비구동 연결→소유 CARLA의 직진·회전·속도·목표 정지·독립 반복입니다. 교사 제어와 모델 제어를 구분하고 충돌·차로 침범·전체 실패를 보존합니다. 모델 자동 승격과 실차 구동은 별도 승인 대상입니다.

[입력 검증 종료 후 학습 준비 현황](../../../../storage/experiments/plans/2026-10-12/map_learning_readiness_after_CPU_boundary_v1.json)에 완료와 남은 조건을 구분했습니다. 군별 20,000회는 **제안한 고정 비교 종료점**이지 학습 중인 횟수나 성능 보장이 아닙니다.

이번 95.29초는 CPU 입력 시험의 실제 시간입니다. 새 trainer 구현·전체 학습·독립 폐루프 시간은 아직 측정하지 않았습니다. 크레딧 잔액·정확한 미래 토큰 비용·완료 날짜·공개 모델과 동급 성능을 추정해 약속하지 않습니다.
