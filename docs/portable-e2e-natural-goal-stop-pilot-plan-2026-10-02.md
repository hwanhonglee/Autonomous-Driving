# 목표 지점까지 주행하고 자연스럽게 정지하는 데이터 시험

<!-- HH_261002 - Separate the prospective normal goal-stop teacher pilot from learned-model and feature approval. -->
이번 작업은 **학습 모델의 시험이 아니라, 정지까지 포함한 실제 CARLA 교사 데이터 1회 수집**입니다.
직진 중 감속하고 목표 부근에서 멈춘 뒤 2초 유지하는 전 과정을 기록합니다.
새로운 head를 추가하거나, 기존 모델이 정지할 수 있다고 선언하는 작업은 아닙니다.

## 무엇을 확인하나요?

| 항목 | 사전 고정 조건 |
|---|---|
| 장소·경로 | Town07, ClearNoon, 기존 210.598 m 직진 경로 |
| 반복 수 | 가운데 출발 1회, seed `2026102200`; 실패해도 삭제·자동 재시험하지 않음 |
| 교사 목표 속도 | 2.4 m/s, 약 8.64 km/h; 실제 속도는 원 측정값 그대로 기록 |
| 정지 완료 | 후륜 기준 목표까지 경로·직선 거리 모두 1 m 이내, 지나치지 않음, 실제 속도 0.05 m/s 이하로 2초 유지 |
| 최대 길이 | 총 시뮬레이션 140초: 준비 1.2초 + 주행 최대 132.3초 + 정지 후 6.5초 |
| 기록 | 차량 상태 20 Hz, 6개 카메라 10 Hz, 원 제어·수신 ACK·원 영상 SHA·차체/연속 이동 여유 |
| 데이터 앵커 | 주행 시작 4초부터 실제 2초 정지 유지 완료까지 모든 카메라 시점; 최소 30초 분량 |
| 후속 정지 기록 | 추가 6.5초는 실제 6.4초 미래 정답을 위한 문맥; 학습 앵커로 세지 않음 |

기존 순항 수집기의 “매 순간 2.4 m/s로 덮기”와 “정상 브레이크를 0으로 만들기”는 사용하지 않습니다.
목표 정지 제어기가 지정한 감속 목표와 정상 브레이크를 보존하며, 원 BasicAgent 위험 대응도 유지합니다.
수동 1단 준비·워밍업·첫 실제 제어가 **동일 차량의 실제 스냅샷/ACK**와 맞는지도 별도로 검사합니다.

## 성공해도 아직 학습할 수 있다고 단정하지 않습니다

1. 사전 선언과 자원 소유 확인 후 로컬에서 교사 주행 1회를 실행합니다. 원 상태·영상·실패 자료를 모두 보관합니다.
2. 소유권·상태/카메라 시간·ACK·목표 정지·차체와 연속 이동 안전 여유를 검사합니다.
3. 별도 새 정지 데이터 검사에서 각 앵커의 **실제 64개 미래 위치·속도와 물리 한계**를 전수 확인합니다. 정지 부근의 곡률이 계산 불가능하거나 한계를 넘으면 통과로 바꾸지 않습니다.
4. 이 1회가 적격이어야 여러 TRAIN/별도 HOLDOUT 장면을 사전 구성합니다. 그 다음 기존 intent/stop-distance head에 실제 목표·교사 단계와 연결한 GO/BRAKE/HOLD 정답을 제공하는 학습을 설계합니다.

현재 원본은 `PENDING_QA`이며 학습·실차 허가가 없습니다. 교사 완료는 learned E2E 정지 성공이 아닙니다.
목표는 **MF-02 경로·차로 주행 / RTE-04 경로 종점 정지**를 위한 데이터 공백을 메우는 것이고,
후륜 기준 목표 정지와 범퍼 기준 정지선 시험도 서로 다릅니다.
공식 기능 승인은 계속 **메인 0/9, 하위 0/30**입니다.

## 실행 주체와 결과 위치

로컬에서 루트 작업자가 공유 포트·다른 시험과 겹치지 않도록 소유권을 확인하고 실행합니다.
이번 단계에는 원격 GPU 학습·패키지 설치·실차 제어가 없습니다.
결과는 `storage/experiments/validation/2026-10-02/town07_natural_goal_stop_teacher_v1/pilot_00/`에 보관합니다.

동결된 실행자는 [소유 실행자](../tools/e2e/run_owned_town07_natural_goal_stop_20261002.py),
[수집기](../tools/e2e/collect_town07_natural_goal_stop_20261002.py),
[데이터 범위 계약](../tools/e2e/town07_natural_goal_stop_task_20261002.py)입니다.
루트는 `contract → declare → preflight → execute → summary` 순서로 실행하며,
선언 뒤에는 정확한 `--plan-sha256`을 전달합니다.
계약 검토와 합성 검사 36개는 통과했으나 **실제 pilot 실행과 미래 정답 승인은 아직 별도 단계**입니다.
