# Portable E2E 기본 주행 재설계와 학습 계획

<!-- HH_261001 - Separate measured failures from proposed architecture, training budgets and deployment claims. -->

기준일은 2026년 10월 1일이다. 권장안은 **연속 카메라 영상에서 경로 모양과 속도 계획을 따로 학습하는 자체 경량 모델**이다. 기존 체크포인트에 기능 head를 계속 추가하는 대신, 기본 주행을 위한 새 버전을 별도로 만든다. 기존 모델은 같은 조건으로 비교할 기준선으로 보존한다.

이 문서는 사용자가 제공한 재설계 프롬프트의 산출물인 설계안과 첫 실행 과제다. **이번 작업에서 새 모델 구현, 패키지 설치, CARLA 실행, 원격 본 학습, 데이터 삭제는 하지 않았다.** 아래 텐서 크기·데이터 수·학습 예산·합격 목표는 별도 표시가 없는 한 제안값이며, 이미 얻은 성능이 아니다. [현재 결과 목록](assets/validation/2026-10-01/README.md)과 연결해 읽는다.

## 1 현재 실패의 핵심 진단

### 확인한 사실과 아직 모르는 것

학습이 전혀 없었던 것은 아니다. 전체 모델 학습, 선택기 전용 학습, 추가 학습과 실제 학습 모델 제어 시험을 수행했다. 다만 충분히 잘 주행하는 모델은 아직 확보하지 못했고, [기능 로드맵](portable-e2e-feature-roadmap.md)의 승인된 폐루프 기능은 **0/30**이다. 코드 검사 통과 수와 학습 실행 수는 이 완료 수에 더하지 않는다.

- TRAIN은 2,787개 앵커, 전문가 주행 8개 episode다. 직진 1,949개, 우회전 534개, 좌회전 304개이며 회전은 방향별 한 episode다. 0.5–2.5m/s 저속 앵커는 35개뿐이다. 서로 겹치는 미래 창을 독립 주행 사례로 세면 안 된다.
- 과거 K1은 한 batch에 직진 2개·좌/우회전 각 1개를 이미 섞었다. 따라서 단순한 프레임 수 불균형만으로 학습 비중 부족을 단정하지 않는다. **회전 장면의 독립 다양성 부족**이 더 직접적인 문제다. W1/W2는 다른 순환 표본 순서를 사용한다. [K1 학습 실행기](../tools/e2e/run_moving_multiroute_recovery_k.py)
- W1 2,999회, W2 11,996회 업데이트를 비교했다. W2는 같은 데이터를 더 반복한 것이며, 알려진 DEV의 6.4초 오차 9개가 모두 악화했다. 합산 ADE는 2.270810→2.352248m, 우회전 ADE는 4.169466→4.255285m였다. 이는 지금 설정에서 반복 증가가 해법이 아니었다는 근거이지, 새 데이터와 다른 학습 계획도 실패한다는 증거는 아니다. [고정 W1/W2 결과](assets/validation/2026-10-01/warmup_supervision_ab/w2_duration_v1/README.md)
- W1은 실제 Town07 150초 시험에서 210.60m 중 200.51m 진행했다. 원래 차선 밖으로 차체가 나간 것으로 판정된 것은 아니지만, 보수적 연속 sweep의 10cm 여유 검사는 2,999구간 중 17구간 실패했고 최저 원래 경계 여유는 7.81cm였다. 미완주와 안전 여유 미달을 함께 남긴다. [실제 차체 검사](assets/validation/2026-10-01/selector_phase_ab/W1_RECORDED_BODY_LANE_AUDIT.md)
- 최근 실제 A/B의 첫 급감속은 0.3초 목표속도가 약 0.87/0.78m/s로 양수일 때도 발생했다. 큰 정지 유지 제동은 정지 후에 나왔다. 4,200개 원시 상태·명령 대조에서 이 시험의 정렬 오류는 확인되지 않았다. **전체 데이터셋의 정렬까지 증명한 것은 아니다.** [급정지 역추적](assets/validation/2026-10-01/selector_phase_ab/stop_mechanism_forensic_v1/REPORT.md)
- 작은 TRAIN 12장면 암기는 이미 성공했다. U/V에서는 경로 모양과 시간 진행을 분리하고 곡률을 보고 미리 감속하면 큰 우회전 뒤까지 이어지는 기준 경로를 만들었다. 하지만 정답 경로를 제공한 계산이며, 신경망의 영상 인식·실제 제어 성공은 아니다. 이후 차체 검사에도 잔여 문제가 있었다. ### 가장 유력한 가설 세 가지

**가설 1은 데이터가 필요한 상태와 회복 행동을 충분히 보여주지 못한다는 것이다.** 방향별 한 회전 episode, 적은 저속 자료, 준비 대기와 강제 종료 정답은 실제 순항·정차·재출발을 대신하지 못한다. 반대 근거는 기존에도 행동 균형 표본 추출을 했고 일부 직진 성능은 실제 개선됐다는 점이다. 판별은 새로운 적격 episode를 추가한 모델과 기존 자료만 쓴 모델을 같은 구조·학습 예산으로 비교한다. 좋아지면 실패 상태의 전문가 회복 자료를 확대하고, 좋아지지 않으면 TRAIN/새 DEV 곡선과 행동별 오차로 구조·정답 문제를 구분한다.

**가설 2는 후보 선택과 가까운 미래의 제어 목적이 학습 목적에 충분히 연결되지 않는다는 것이다.** 현재는 한 시점의 영상만 사용하고, 긴 미래를 잘 맞춘 후보의 선택 점수를 학습한다. 실제 제어기는 0.3초 속도를 읽는다. 선택 후보와 더 좋은 후보 사이의 차이, 일부 0속도 경계의 직접 기울기 0은 이미 관측됐다. 반대 근거는 12장면 암기 성공과 U/V의 기준 경로 표현 가능성이다. 새 버전에서 같은 데이터로 현재 영상만 보는 모델과 과거 영상도 보는 모델을 비교하고, 가까운 속도·재출발·전체 회전을 따로 평가한다. 시간 정보가 이득이 없으면 제거한다. 큰 모델이나 BEV 도입을 자동 결론으로 삼지 않는다.

**가설 3은 작은 페달 명령과 CARLA 저속 응답의 조합이 정지를 증폭한다는 것이다.** 최근 양수 목표속도에서 급정지가 발생했고, 현재 추종기는 속도 오차가 작으면 스로틀도 거의 0이 되는 P 제어다. 반대 근거는 전문가가 같은 위치를 통과했고, 과거 다른 시험에서는 모델의 0속도 예측도 실제로 관측됐다는 점이다. 첫 판별 과제는 아래 Town07 스로틀 격리 8회다. 차량 응답 문제가 확인돼도 모든 과거 정지를 그것 하나로 설명하지 않는다.

실제 폐루프 비교의 제어기를 확정하기 전에는 가설 3을 확인해야 한다. 반면 새 모델 계약·데이터 분할·기존 영상의 시간 문맥 구성·지도 모델 설계는 병렬로 진행할 수 있다. 한 저속 제어 문제나 합성 기준 경로의 미세 기하 검사가 모든 모델 연구를 무기한 막는 선행조건은 아니다.

## 2 권장 구조와 쉬운 설명

### 비교한 세 구조와 선택

| 후보 | 얻는 것 | 남는 문제와 판단 |
| --- | --- | --- |
| A 기존 구조 최소 수정 | 구현량이 적고 원인별 A/B가 쉬움 | 현재 영상·밀집 경로 의존·후보 선택을 그대로 가져감. 비교 기준선으로 유지 |
| B 자체 경량 연속 영상 모델 | 공간 특징과 최근 움직임을 보존하고 경로와 속도를 분리 | 새 데이터 계약과 학습 필요. **권장안으로 선택** |
| C TCP 계열 공개 비교 기준 | 검증 가능한 궤적/제어 학습 구조를 비교할 수 있음 | 원본은 단안·CARLA 0.9.10.1 환경. 현재 6카메라·0.9.15와 직접 동등하지 않음. 후속 비교용 |

[TCP 공식 저장소](https://github.com/OpenDriveLab/TCP)는 궤적과 직접 제어 예측을 결합한다. 원본 의존성을 지금 설치하거나 공개 순위를 우리 성능으로 옮겨 말하지 않는다. B를 먼저 선택하는 이유는 현재 센서·이식성·10Hz 제약에서 각 변경의 효과를 분리할 수 있기 때문이다. B가 TCP, VAD, METEOR 또는 실차 상용 모델 수준이라는 근거는 없다.

```text
최근 0.8초의 6카메라 영상 ─→ 공유 CNN과 영상 위치 특징 ─┐
카메라 보정값과 차량 이동 ─→ 시간·시점 보정 특징 ─────┤
차량 상태와 내비게이션 ──────────────────────────────┤
선택적 주변 지도 ─→ 신뢰도와 유효성 검사 ────────────┘
                          ↓
               공간·시간 정보를 결합한 장면 표현
                          ↓
             경로 모양       속도와 정지 의도
                    └──────┬──────┘
                   물리적 실행 가능성 검사
                          ↓
               6.4초 궤적과 속도·가속도 계획
                          ↓
             차량별 추종기와 독립 안전 계층
                          ↓
                 Autoware 또는 다른 시스템
```

쉽게 말하면 현재 모델은 주로 “지금 사진과 정밀한 경로”에서 답을 고른다. 권장안은 “방금 전부터 무엇이 움직였는지”도 보고, **어디로 갈지와 얼마나 빨리 갈지를 별도로 결정**한다. 차량마다 다른 스로틀 값은 별도 추종기가 계산한다. 화살표가 있다고 모든 기능이 구현됐다는 뜻은 아니다.

### 입력과 연산량 제안

학습 영상은 `[B,5,6,3,180,320]`이며 시점은 −0.8/−0.6/−0.4/−0.2/0초다. `B`는 한 번에 학습하는 묶음 수다. 공유 4단계 CNN 뒤의 6×10 공간 격자를 지우지 않고 `[B,5,6,60,128]` 특징으로 보존한다. 카메라별 식별자, 영상 위치·광선 방향, 보정값 `[B,6,16]`, 상대 차량 이동·시간 차이·유효 마스크를 함께 넣는다.

차량 상태는 기존 13개 특징의 10프레임 이력을 비교 시작점으로 유지한다. 내비게이션 명령과 기계적 상태를 별도로 이름 붙이고 마스크를 검사한다. 장면 결합은 폭 128, query 32개, cross-attention 2층을 첫 제안으로 한다. 전체 영상 token끼리 큰 self-attention을 돌리는 구조는 먼저 채택하지 않는다. 초기 용량 목표는 약 2–5백만 parameter이며 실제 구현 후 계산해야 한다.

추론에서는 새 6카메라 묶음만 CNN에 넣고, 과거 특징을 유한한 캐시에 보관한다. 위 특징의 5시점 FP16 값 자체는 약 0.44MiB이며 중간 activation과 실행 메모리는 별도다. 학습 중 CNN이 업데이트되므로 오래된 특징 캐시를 그대로 학습에 재사용하면 안 된다. 시작·리셋·보정값 변경 시 캐시를 비우고, 부족한 과거는 마스크로 표시한다. 미래 영상, 다른 episode의 과거, 현재 영상을 복제한 가짜 이력은 금지한다.

이 표현은 공간 정보를 유지한 영상 특징이지 검증된 3차원 BEV 지도가 아니다. 깊이 없이 과거 픽셀을 정확히 지면에 투영했다고 주장하지 않는다. [BEVFormer](https://arxiv.org/abs/2203.17270)는 공간·시간 정보를 BEV query로 결합하는 공개 사례지만, 첫 기본 주행 버전에 BEV가 필수라는 근거는 없다. 영상 격자 방식의 한계가 확인될 때 별도 BEV 비교를 한다.

### 경로와 속도 출력

첫 기본 주행 버전은 **명시된 내비게이션에 대한 경로 1개**를 출력한다. 12개 후보의 생성·선택을 동시에 복구해야 하는 부담을 먼저 없앤다. 교차로 양보나 장애물 회피처럼 여러 행동이 실제로 필요한 단계에서만 최대 3개 후보와 위험 점수를 도입한다. 후보 수를 줄이면 모든 상황이 해결된다는 주장은 하지 않는다.

경로 모양은 차량 기준 좌표에서 거리 0–64m의 곡률 매듭 33개로 표현한다. 초기 위치·방향은 현재 차량 상태와 연결하고, 매듭을 보간한 뒤 0.25m 간격으로 적분한다. 속도 head도 같은 33개 거리 매듭의 선호 속도를 출력한다. decoder가 물리 제약을 적용하고 시간 진행을 계산해 최종 시간 0.1–6.4초의 XY·속도 64개를 만든다. 여기에 가까운 가속도 보조 출력과 `GO / BRAKE_TO_STOP / HOLD` 의도, 유효한 정지 위치를 둔다. 현재 속도는 관측된 값으로 고정하며 편의를 위해 낮추지 않는다.

공간 정답은 완전한 원본 episode에서 실제 전문가가 지나간 경로를 최대 64m까지 읽고, 기록된 유효 거리만 감독한다. 6.4초 자료로 64m 전체 정답을 만들어내지 않는다. 경로/속도/방향의 공간 prefix mask와 시간 미래 mask를 별도로 둔다. 밀집 내비게이션 참조를 보조 정답으로 쓰는 경우에는 그 출처와 별도 loss를 표시하고 전문가 정답으로 바꾸어 부르지 않는다. 낮은 속도에서 학습되지 않은 먼 곡률 때문에 지금 제동하지 않도록 retiming의 활성 거리를 운용 속도 상한·6.4초 범위·제동 거리로 제한하고, 필요한 활성 거리의 유효 정답이 부족한 cohort는 보강한다. 추론에는 TRAIN의 미래 mask를 주지 않으며, 검증된 경로 유효성/불확실성이 충분한 제동 거리를 지원하지 못하면 명시적으로 거절한다. 30km/h에서 6.4초 진행에 제동 여유까지 요구하면 64m가 부족할 수 있으므로, 확대 전에 80m 이상 공간 preview와 해당 정답을 별도 revision으로 검증한다.

속도 학습값은 softplus와 같은 부드러운 양수 표현을 사용하고, 제한 전 속도에도 정답 손실을 준다. hard clamp 뒤의 0속도만 유일한 학습 경로로 두지 않는다. softplus만으로는 정확한 0을 만들지 못하므로, 실제 정지 유지와 재출발은 별도 의도·정지 위치·hold hysteresis로 처리한다. **HOLD는 관측 속도 ≤0.05m/s 부근에서만 진입**하고, 주행 중 정지 요청은 실제 현재 속도에서 이어지는 BRAKE_TO_STOP이어야 한다. HOLD 선택으로 주행 중 미래 전체를 즉시 0으로 대체하지 않는다. 목표 정차 뒤 출발은 새 출발 요청을 받아야 하며, 이후 신호/선행차 hold 해제는 관련 장면 근거가 필요하다. 타이머만으로 재출발하지 않는다. 준비 대기를 신호 정지로, 강제 종료를 목표 정차로 라벨링하지 않는다. 현재 단계의 정지 이유는 검증된 목표 정차부터 시작한다.

U/V의 경로 길이 재계산·곡률 속도 상한·진입 전 감속·초기 속도 적합성 검사를 재사용한다. 단, 제공된 정답 경로 대신 **모델이 생성한 경로**에 적용한다. [현재 V 소스](../tools/e2e/probe_curvature_preview_v.py)의 횡가속도 1.5m/s²·감속 2m/s²·가속 1.5m/s²는 연구 설정이며 실제 차량의 보편적 한계가 아니다. 원본 기준이나 기존 gate를 완화하지 않는다.

학습 decoder는 Torch의 보간·적분·속도 envelope·시간 표본화를 사용해 유효 구간에서 역전파한다. source의 NumPy 계산을 그대로 호출하고 미분된다고 가정하지 않는다. min/max와 구간 선택 경계에서는 기울기가 끊기거나 특정 분기로만 전달될 수 있으므로, 제한 전 속도와 공간 형상 손실도 유지한다. 곡률 상한 활성·감속 경계·정지·재출발에서 유한 기울기와 수치 미분 대조를 확인한다. 이 확인을 통과하기 전에는 projected XY 손실만으로 모양과 속도가 함께 학습된다고 주장하지 않는다.

순간 속도, 구간 평균 속도, 곡선 거리, XY chord 속도를 계약에서 구분한다. 시간 적분의 이동 거리로 경로를 읽고, 기존 출력과 비교할 속도는 최종 XY 간 거리/0.1초로 재계산한다. 별도 가속도·jerk·곡률·차체 검사도 적용한다. 현재 상태에서 물리적으로 이어질 수 없는 계획은 거절하거나 별도 안전 감속으로 넘기며, 시작 속도를 바꾸어 합격시키지 않는다. 이 수학적 일관성이 실제 타이어·조향 응답까지 보장하지는 않는다.

현재 route-relative decoder의 작은 경로 편차 표현을 “회피가 절대 불가능하다”고 단정할 수는 없다. 다만 밀집 경로 접선에 강하게 묶인 구조만으로 큰 차선변경·합법적 회피를 입증하지 못했다. 새 버전은 경로 자체를 생성하고 경계·객체 자료를 학습할 여지를 둔다. 회피/차선변경 자료 없이 해당 기능이 생겼다고 말하지 않는다.

### 가까운 제어와 긴 경로를 함께 학습

손실을 0.1–0.5초, 0.6–2초, 2.1–6.4초 구간으로 나누고 각 구간을 정규화한다. 첫 제안은 비중 0.4/0.3/0.3이며 변경 시 별도 비교한다. XY·속도·정지 의도·초기 가속도·jerk·연속 추론의 일관성을 각각 보고한다. 정지 구간의 의미 없는 방향과 불확실한 가속도 라벨은 마스크를 둔다. 긴 회전을 몇 초 늦게 시작해 당장만 통과하는 결과는 전체 회전 완료 검사에서 실패한다.

직접 페달 예측은 첫 주 출력으로 채택하지 않는다. 차량 이식성을 위해 경로·속도·가속도를 공통 출력으로 두고, 추종기에 차량별 구동 보정과 acceleration feedforward, 제한된 PI 피드백·anti-windup을 넣는다. 스로틀/제동 동시 적용 금지, 조향 변화율, 정지 유지·재출발 상태, 실제 명령 ACK를 기록한다. 정체 원인을 확인하기 전 스로틀 하한을 임의로 올리지 않는다.

### 내비게이션과 정밀지도 의존성

현재 입력은 약 1m 간격의 128개 밀집 중심선 점이다. 이것을 유지하면서 “HD map 없이 영상으로 주행한다”고 부르면 안 된다. [현재 경로 tensor화](../learning/portable_e2e/torch_dataset.py)

첫 구조 비교는 기존과 같은 밀집 경로를 받는 별도 `dense_nav_v2`에서 한다. 이후 명령·유효 마스크·8개 성긴 waypoint·목표 정차 요청을 받는 `coarse_nav_v2`와 비교한다. 성긴 waypoint는 대략 10m 이상 간격과 위치 잡음으로 구성하되, 차로 접선·폭·곡률·정지선 정답을 숨겨 넣지 않는다. CARLA 중심선에서 단순히 점 수만 줄인 비교는 입력 해상도 비교일 뿐, 실제 HD map 비의존성 증명이 아니다. 실제 운용의 내비게이션 경로 공급원까지 별도로 검증해야 한다. 밀집 경로로 자동 fallback해서 무지도 시험으로 세지 않는다.

### 지도 모델은 병렬로 개선하되 처음부터 결합하지 않음

지도 모델은 영상에서 도로·차선·횡단보도·정지선·표지판·신호등 구조물을 인식하는 작업과, 깊이·위치를 이용해 그 정보를 누적하는 작업을 나눈다. 신호등의 현재 색은 시간에 따라 변하는 상태이며 영구 지도 항목과 구분한다. 현재 누적 차선 IoU 9.34%/21.88%는 개선 대상이지 완성된 정밀지도가 아니다. [전체 누적 평가](assets/validation/2026-10-01/map_geometry_full_projection/README.md)

온라인 출력은 주변 도로/차선 확률·선 또는 격자, 좌표계·생성 시각·관측 나이·신뢰도·관측 가능 영역·pose/depth 불확실성을 전달한다. 오래되거나 보정값이 다른 지도는 거부하며 “빈 칸=안전한 도로”로 처리하지 않는다. 주행 모델에는 선택적 입력으로 붙이고, 지도 없음·틀린 지도·지연된 지도·정상 지도의 비교 및 지도 dropout 학습을 한다. 처음에는 shadow로만 연결한다.

오프라인 지도는 원본 주행 기록과 위치 추정을 함께 누적하고 반복 관측·차선 연결 관계를 검증한다. `정답 깊이+정답 pose`, `예측 깊이+정답 pose`, `예측 깊이+추정 pose`의 세 결과를 분리한다. 정답 깊이로 투영한 결과를 카메라 단독 정밀지도라고 부르지 않는다. 주행과 지도 모델의 가중치·학습·지연 예산은 우선 분리한다.

## 4 데이터 확보와 본 학습 계획

### 새로운 정보의 확보 순서

먼저 9개 적격 episode의 수집 pilot을 한다. 직진·좌회전·우회전에 대해 TRAIN/새 DEV/봉인 TEST용으로 서로 다른 물리적 도로·교차로 그룹을 한 개씩 미리 정한다. 이어 **최소 30개 완전한 episode**, TRAIN 18/새 DEV 6/TEST 6으로 확장한다. 각 split에 세 방향을 균형 배치한다. 이는 기본 동작의 첫 본 학습 규모이지 전체 기능 합격에 충분하다는 보장이 아니다.

30episode 단계의 고유 corridor 최소 제안은 방향별 TRAIN 3개·DEV 2개·TEST 2개로 총 21그룹이다. TRAIN은 각 그룹의 반복을 최대 2개로 시작한다. 80–120episode 확대 시에는 방향별 TRAIN 8개 이상·DEV/TEST 각 3개 이상으로 독립 장소도 늘린다. 같은 도로에서 반복 촬영한 횟수는 고유 장소 수에 더하지 않는다. 이 규모가 수집 가능하지 않으면 실제 고유 그룹 수와 좁아진 평가 범위를 밝히고, 반복 영상으로 다양성 목표를 달성했다고 말하지 않는다.

각 episode는 60–120초의 정상 주행과 가능한 행동 단계를 기록한다. 출발·0.5–1.5m/s 유지·감속 후 재가속·정상 순항을 먼저 확보하고, 완만한 곡선·좌/우회전, 작은 차로 오차 회복, 자연스러운 목표 정차·hold·재출발 순서로 확장한다. 특히 Town07 실패 위치 10–30m를 직접 포함한다. 이미 모은 40–120m 자료나 소스/QA 보류 327앵커를 이를 대신하는 승인 데이터로 쓰지 않는다.

실패 상태를 재현한 뒤 검증된 전문가가 회복하는 주행을 기록한다. 실패 모델의 궤적을 좋은 정답으로 복사하지 않는다. 정상/회복 비율 70/30은 **감독되는 학습 노출 수**의 초기 제안이며 episode 수의 비율이 아니다. 실제 유효량과 행동별 결과로 조정한다. episode 내 연속 앵커를 반복 추출할 때 고유 episode·경로 수와 노출 횟수를 함께 기록한다. 이전 적격 자료는 일정 비율 복습하고, 불합격 라벨은 망각 방지라는 이유로 섞지 않는다. 회복 상황을 학습하는 방향은 [ChauffeurNet 원 논문](https://arxiv.org/abs/1812.03079)의 동기와 맞지만, 센서/모델 조건이 다른 그 성능을 이 계획의 보장으로 사용하지 않는다.

분할의 단위는 road/junction corridor 그룹과 전체 episode다. 같은 물리적 구간의 속도 변형·seed 반복·렌더 변형·인접한 겹침 경로는 같은 split에 둔다. 과거 Town03 DEV 665개는 이미 반복 확인한 회귀 검사로 유지하고 새 독립 평가라고 부르지 않는다. **이미 본 Town의 새로운 겹치지 않는 도로/episode도 유효한 within-Town 평가**가 된다. 완전히 안 본 Town은 이후 일반화 시험이며, 그것을 기다린다고 모든 본 학습을 막지 않는다.

자료 admission은 6카메라 시간 정렬, 입력/출력 좌표, 20Hz 원시 상태, 실제 명령 수신, 차체 여유, 물리적으로 가능한 미래, 행동 단계와 자연/강제 정지 구분을 포함한다. 하나의 실패 실행을 잘라 분모를 바꾸어 합격시키지 않는다. 적격 정상 구간의 사용 여부는 별도 사전 정의한 데이터 계약으로 결정하고 원본 실패 상태를 보존한다.

### 두 단계 학습으로 원인을 분리

**먼저 데이터 효과를 확인한다.** 현재 구조와 같은 부모 가중치를 사용해 기존 TRAIN과 기존+새 적격 TRAIN을 같은 순서 정책·batch 4·업데이트 수로 비교한다. AdamW LR `3e-5`, weight decay `1e-4`를 시작점으로 두고, 새 계획에는 500회 warmup과 마지막 `3e-6`까지 cosine 감쇠를 명시한다. 기존 상수 LR W2와 다른 실험이다. 3,000회는 배선/진행 방향 확인용이며 최종 학습 완료라고 보고하지 않는다. 새 DEV를 0/1,500/3,000회에서 보고, 유망하면 6,000/10,000/15,000회까지 연속 진행한다.

cosine의 전체 길이는 시작 전에 15,000회로 고정한다. 3,000회 뒤 연장할 때 optimizer/scheduler를 다시 시작하지 않는다. 위 평가 시점은 데이터 효과 단계의 규칙이며, 아래 1,000회 간격은 새 구조 단계에만 적용한다.

**이어서 구조 효과를 확인한다.** 동일한 새 자료로 A 기준선, B 현재 영상만, B 5시점 영상을 한 고정 seed에서 비교한다. 기본 목표는 batch 16, arm당 최대 40,000회 업데이트다. 실제 메모리에 따라 batch 8+gradient accumulation 2로 유효 batch를 유지한다. 1,000회 warmup, LR `1e-4`→`1e-5` cosine을 첫 제안으로 하되 TRAIN 불안정 시 계획 revision을 만들고 변경한다. 기준선에도 같은 새 데이터·노출 예산을 주며 학습량 차이를 구조 효과로 읽지 않는다.

구조 효과 단계의 세 arm은 새 초기화로 시작한다. 일치하는 공유 CNN 층에는 같은 초기 tensor를 복사하고, W1으로 계속 학습한 A와 새 초기화 B를 구조 비교로 섞지 않는다. 기존 W1은 별도 운용 기준선으로 평가한다. B 두 arm은 parameter 수·초기값·loss·decoder·내비게이션·감독 앵커가 같고, 현재 영상 arm은 과거 token만 마스크한다. 공개 사전학습을 도입하면 별도 축으로 선언한다. 여기서 update는 optimizer 갱신 한 번이며 accumulation 2는 microbatch 두 번을 합친 한 update다.

30개 episode가 10Hz로 60–120초이면 원시 앵커는 대략 18,000–36,000개이고, 미래/과거 확보·QA 후 유효 TRAIN은 그보다 적다. 40,000×16=640,000 노출이므로 유효 TRAIN이 12,000–24,000개라면 약 27–53회 반복에 해당한다. **반복을 많이 했다는 사실과 독립 정보가 많다는 사실은 다르다.** DEV가 먼저 나빠지면 반복을 끝까지 채우지 않는다. pilot이 지나치게 작은 경우 80–120episode 수준으로 확대하고 본 학습 예산을 다시 계산한다.

새 구조 평가는 1,000 optimizer update마다 한다. 새 DEV의 episode-macro selected ADE 6.4초를 patience 통계로 두고, 이전 best 적격 checkpoint 대비 1% 이상 개선이 5회 연속 없으면 종료한다. 모든 후보/실패 checkpoint 기록은 남긴다. best 적격 조건은 유한 출력·물리 gate 및 사전 고정 중요 집단 비퇴행이며, 조건을 충족한 후보가 없으면 미채택이다. 데이터 효과 단계는 그 단계의 고정 평가 시점에서 3회 연속 개선 없음으로 종료한다.

안전 중요 집단의 5% 퇴행 한계는 **같은 새 DEV를 평가한 고정 현재 기준선**과 비교한다. 충돌 같은 0회가 필요한 항목에는 5% 허용을 적용하지 않는다. 단일 후보 B에도 동일한 selected 지표를 계산하고, 기존 A의 selected/oracle 차이는 별도 진단이다. TRAIN/DEV 곡선·방향·속도 구간·정지 이유·회복·맵·렌더별 수치를 남긴다. 평균 하나로 오른쪽 회전이나 정지를 가리지 않는다.

한 seed의 screening에서 개선이 확인된 설정만 3seed로 확인한다. 시간 영상의 이득이 없으면 같은 용량의 현재 영상 모델을 남긴다. 밀집/성긴 내비게이션 비교는 그 다음 별도 축으로 수행한다. 모든 조합을 처음부터 무작정 학습하지 않는다. 기존 작은 TRAIN 암기·T/U/V 최적화를 이유 없이 다시 수행하지 않는다.

### 실제 데이터와 시뮬레이션을 섞는 방법

실차 기록의 비구동 replay 준비는 CARLA 개선과 병행할 수 있다. 공개 또는 자체 기록은 라이선스·센서 timestamp·보정값·차량 이동·행동 label을 먼저 확인한다. 카메라 수, 위치, 화각, 해상도는 rig별로 표현하고 결측 마스크를 사용한다. TF만 바꾸면 시야가 복원되는 것은 아니며, 실제 보이지 않은 영역이나 다른 렌즈 특성은 학습·평가가 필요하다.

초기 혼합 비율로 적격 sim 80%/real 20%를 제안한다. 실차 label이 없는 signal/trajectory/occupancy 항목은 손실을 마스크하고 “없음” 정답으로 채우지 않는다. 실차 지도·객체 정답만 있는 자료는 표현 학습에 쓸 수 있어도 주행 계획 정답이 있는 자료와 같은 역할은 아니다. real DEV는 별도로 유지하고, sim 성능 보존·실차 replay를 확인한 뒤 실제 비율을 늘린다. 최종은 shadow→안전 폐쇄 시험장 순서이며 CARLA 통과가 실차 허가는 아니다.

지도 모델은 같은 틱 OFF/ON appearance TRAIN 보강과 새 도로 DEV를 우선 확보하고, 기존 차선 성능 보존·새 도로 차선 누락을 동시에 평가한다. 먼저 class-balanced segmentation과 차선 경계/연결 손실을 한 번에 하나씩 비교한다. 과거 실패한 단순 차선 가중치 2배를 새로운 해법으로 반복하지 않는다. 깊이/pose 예측과 결합하기 전 인식 개선이 실제 누적 지도에도 남는지 확인한다.

```bash

python3 -B tools/workspace_python.py \
```

이번 작업에서는 위 **trial 0 preflight만 실제 실행해 exit code 0**을 확인했다. source/asset pin·CARLA Python API import·기존 실행 충돌·2440/2441/2442 포트·공간 검사를 통과했고 `simulator_started=false`, 카메라 0개·모델 추론 0회였다. 당시 여유는 6,360,846,336B, 필요 하한은 5,502,926,848B였다. 실제 8회 결과나 진입 속도 조건까지 확인한 것은 아니며, execute 전에 다시 검사한다.

이 시험은 약 2.4m/s 진입의 **무제동** 응답만 판별한다. 과거 급정지 직전의 약 0.8–1.4m/s와 작은 제동까지 같지 않다. 두 팔 모두 정상이어도 저속/제동 기여가 완전히 반증된 것이 아니다. 다음 더 낮은 속도·작은 제동 시험이 필요하면 별도 한정 계획으로 선언한다.

## 6 성공과 실패에 따른 다음 조치

### 첫 스로틀 실험의 분기

- A에서 반복 급정지하고 B에서 완화되면 낮은 구동 명령의 기여 근거가 된다. 차량별 구동 보정과 feedforward/PI를 설계한 뒤 전문가 궤적에 연결해 확인한다. 모델 스로틀 하한만 올려 승격하지 않는다.
- 두 팔 모두 급정지하면 스로틀 크기만의 설명은 부족하다. 차량 physics/변속 상태/접촉/저속 제동을 확인할 추가 계측을 한정한다. 새 모델/데이터 작업은 계속 병렬 진행한다.
- 두 팔 모두 정상이라면 최근 실패의 더 낮은 속도·작은 제동·모델 목표 변화 조건을 따로 판별한다. 한 음성 결과로 제어 문제 전체가 없다고 선언하지 않는다.
- matched 시작·소유권·원시 기록이 부족하면 효과를 판정하지 않고 해당 회차의 실패를 남긴다. 재시도는 새로운 계획 revision으로 관리한다.

### 모델을 실제로 좋아졌다고 판단할 조건

처음에는 모델을 고정하고 기존/새 추종기를 전문가 궤적에서 비교한다. 그 다음 현재/새 모델 × 기존/새 추종기의 2×2 비교를 같은 경로·실제 속도·시작 상태에서 한다. BasicAgent 기준선도 같은 장면에서 기록하되 전문가 자신의 내부 제어와 공통 궤적 추종 비교를 구분한다. 구조와 제어기를 동시에 바꾸고 모델 개선이라고 말하지 않는다.

첫 폐루프 screen은 직진·좌/우회전·목표 정차 각각 3개 독립 경로에서 3회 반복하는 기본 행동 행렬이다. 기본 속도 9–15km/h부터 시작하고 정차·회복을 포함한다. 개선 후보 선정용이지 9개 영역 승인 시험이 아니다. 전문가도 못 통과하는 장면은 삭제해서 분모를 바꾸지 말고 시나리오/전문가 적합성 실패로 따로 보고한다.

제안 screen 목표는 완주율 ≥90%, 의도하지 않은 연속 정지 2초 초과 0회, 목표 위치 ±1m에서 2초 유지, 직선 순항 속도 MAE ≤0.5m/s다. 충돌·중대한 규칙 위반·차체 10cm 여유 실패는 0회여야 한다. 가감속/jerk는 기존 고정 한계를 유지하고 실제 원시 상태로 계산한다. 낮은 속도를 계속 유지해 끝까지 못 간 경우 완주로 세지 않는다.

센서 입력→decode→추론→검사→최종 명령 수신의 p50/p95/p99를 모두 보고한다. 제안 목표는 p95≤80ms/p99≤100ms이며, 100ms deadline을 넘긴 계획은 정해진 fail-closed 동작으로 처리하고 위반율도 기록한다. 시뮬레이션 시간과 host monotonic 시간을 섞어 빼지 않는다. 실제 캡처 wall-clock을 얻지 못하면 callback 이후 지연과 캡처 시각 불확실성을 구분한다. 현재 모델 forward 약 30ms라는 숫자만으로 end-to-end 10Hz를 주장하지 않는다.

각 행동·경로·seed별로 완주/목표 정차, 충돌, 원래 차선 이탈/10cm 여유, 정지 시간/개입 횟수, 실제 속도/가속/jerk, 지연과 거절을 보고한다. 계획 곡선 PNG와 실제 주행 PNG/GIF를 구분한다. screen 통과 후 30km/h로 확대하고 [기능 정의](../learning/config/portable_e2e_feature_matrix.yaml)의 최소 20/30episode·3seed·날씨 조건 및 봉인 TEST를 충족해야 기능을 승인한다. 60km/h와 실차는 이후 별도 단계다.

TRAIN도 안 맞으면 새 구현·label·decoder를 먼저 확인한다. TRAIN은 맞고 새 DEV가 안 맞으면 데이터 다양성과 regularization을 보강한다. 오프라인은 좋아도 폐루프가 안 되면 실패 상태 전문가 회복 자료와 제어/지연을 개선한다. 기본 성능이 회복되기 전에는 새 행동 head를 늘리지 않는다.
