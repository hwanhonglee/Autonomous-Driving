## 3. 왜 계속 시험했는데 성능 복구가 끝나지 않았나

학습 자체는 여러 번 수행했다. 전체 모델 학습, 이어학습, 선택기만 학습, 데이터 생성·검증을
분리해야 한다. 모든 실험 횟수를 합쳐 큰 모델을 오래 학습한 것으로 해석하면 안 된다.

최신 J는 고정된 경로 후보 위 4개 파라미터 점수 함수를 학습했다. 직진·통합 FDE와 속도는
기준을 회복했으나 우회전 3개 지표, 직진 ADE, 통합 ADE는 실패했다. 이는 전체 모델의 표현력과
경로 생성기를 충분히 다시 학습했다는 증거가 아니다.

또한 연속 10 Hz 표본 수는 독립 장면 수가 아니다. 비슷한 경로를 많이 반복하면 학습 노출은
늘지만 새로운 도로에서 잘 주행하는 능력이 확보되었다고 볼 수 없다. 학습량 부족과 데이터
다양성·정답 적합성·선택 오류를 분리해 확인해야 한다. 현재 결과만으로 원인을 하나로 확정하지 않는다.

## 6. 자원과 시간: 확정값과 추정값

- 확정 범위: PRO6000 GPU 0 한 장만, 두 군 순차 실행. 패키지는 개인 폴더 venv만.
- 확정 계산량: 30,000 step, 전체 파라미터 약 106만 개, 평가 665개 × 두 모델.
- 아직 모름: 실제 step/sec, peak VRAM, 최종 벽시계 시간. 모델 크기만으로 GPU 사용량을 확정하지 않는다.
- 학습 시간 계산: `30,000 / 실측 step/sec + 초기화·저장·평가 시간`.
  5 step/s면 학습 부분 약 100분, 10이면 50분, 20이면 25분이다. 예시 계산이지 현재 성능 예측이 아니다.
- 시작 전 변환·검증·전송은 문제 없이 진행할 경우 30–90분을 임시 작업 예산으로 잡는다.
  실제 데이터 크기·디스크/전송 속도와 변환 오류에 따라 초과할 수 있다.
- 이번 응답은 현황 문서화다. 자동 장시간 학습이나 새 GPU job 시작을 포함하지 않는다.
- 대화 토큰과 GPU 학습량은 별개다. 실제 과금 토큰·남은 계정 한도를 여기서 확인한 값은 없고,
  이 계획이 잔여 크레딧 안에 완료된다고 보장하지 않는다. 긴 학습을 step마다 대화로 보고하지 않고
  시작 확인, 주요 오류, 최종 비교 시점 중심으로 보고한다.

| 순서 | 목표 | 필요한 데이터·정답 | 학습·통과 확인 |
| --- | --- | --- | --- |
| A | 기본 경로·속도 복구 | 품질 통과 직진/좌/우, 속도, 경로 | 현재 전체 모델 K 비교; 이후 신규 seed/경로 |

| C | 신호·정지선 | 동기화 신호 상태, 정지선 거리, 위반 여부 | 필요시 보조 헤드 1개씩, 경로 손실과 공동학습; 빨간불/초록불 오판 분리 |

| F | 차선변경·합류 | 차선 경계/합법성, 전후방 gap, 요청·취소 | 성공뿐 아니라 취소/대기 데이터 포함; 후방 위험·완료율 평가 |
| G | 저속·주차 | 근거리/후방 센서, 후진·최종 자세 | 별도 저속 데이터와 제어 계약, 주차 오차·접촉 평가 |

기능 하나당 헤드 하나를 반드시 붙이는 구조는 아니다. 궤적 정책이 여러 행동을 함께 표현하고,
필요한 경우 객체·차선·신호 등의 보조 손실을 추가한다. 정답이 없는 기능은 loss에서 제외한다.
기존 이동·정지 데이터를 매 batch/캠페인에서 적절히 재노출하고, 이전 기능 고정 평가셋을 유지해
새 기능 때문에 기존 성능이 떨어지는 현상을 검출한다. replay 비율과 loss 가중치는 실험 전에 정한다.

실제 데이터 혼합은 기본 인터페이스와 보정이 준비되는 대로 별도 축으로 진행할 수 있으며,
주차까지 모두 끝날 때까지 기다릴 필요는 없다. 데이터 취득·시간/좌표 정합·장소별 split부터 시작한다.

## 8. NuRec/Cosmos에 얼마를 사용할 것인가

현재 기본 복구 K의 데이터는 **CARLA 100%, NuRec/Cosmos 0%**다. 이번에 새로 설치·다운로드하지 않는다.
후속 예비 실험은 하나의 짧은 장면에서 정합부터 검증한다. 그 뒤 원본 100% 대 원본 80%+
변환/재구성 20%를 예시 후보로 삼되, 아직 확정된 학습 비율은 아니다. 실제 노출 비율을 기록한다.

실제 데이터의 정해진 혼합 비율은 아직 없다. 사용할 데이터셋·센서·라벨·장소 수를 확인하기 전에
실제 50% 같은 숫자를 확정하면 의미가 없다. 생성본과 원본은 같은 split에 두고, 별도 raw-real
평가를 유지한다. NuRec 복원 장면과 실사풍 변환본을 raw-real 데이터로 집계하지 않는다.

## 9. 성능 기대와 남은 범위

이번 K의 목표는 실차 운용 모델 완성이 아니라 **데이터 다양성을 늘린 전체 학습이 기본 성능을
복구하는지 검증**하는 것이다. 이 실험 뒤 모든 Town이나 30개 기능이 동작한다고 약속하지 않는다.
VAD/METEOR 등과 같은 센서·데이터·평가·속도 조건으로 비교한 근거가 없으므로 동급/우월 주장은 불가능하다.
