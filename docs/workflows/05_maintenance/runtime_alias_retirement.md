## 왜 5개를 남겼나요?

남은 항목은 `scripts`, `portable_e2e`, `data`, `datasets`, `artifacts`입니다.

8개를 한꺼번에 제거하는 전환을 먼저 시도했지만, 다음 의존성이 드러났습니다.

1. 과거 학습·수집 코드에는 경로뿐 아니라 **정확한 소스 SHA**까지 고정되어 있습니다.
   import와 경로를 일괄 변경하면 숫자 계산을 바꾸지 않아도 이 검증을 통과하지 못합니다.
2. 과거 manifest의 상대/절대 경로와 실제 파일 위치를 구분해서 읽어야 합니다.
3. 단독 CLI, ROS 설치 환경, CARLA의 Python 검색 경로, 임시 테스트 저장소를 각각 검증해야 합니다.

고정 SHA를 현재 코드에 맞춰 덮어쓰거나 실패 검사를 삭제하지 않았습니다.
일괄 제거 검사 실패 시 8개 링크를 자동 복구했고, 검증되지 않은 소스 변경 **644개를 변경 전 바이트로 복구**했습니다.
그 후 빌드·설치·로그에 한정한 변경을 다시 적용하고 위 720개 검사를 통과시켰습니다.

따라서 현재 상태를 “전체 레거시 제거 완료”로 표시하지 않습니다.
나머지는 고정된 재현 코드와 현재 실행 도구를 구분하는 별도 전환이 필요합니다.
새 데이터 수집·주행/지도 학습보다 이 정리를 우선한다는 순서는 유지합니다.
